## S120–S127 — план полного поиска и сравнения ЕИС (2026-09-27)

Статус: **S120 завершён для `getDocsIP` и публичного аукциона 44-ФЗ;
S121: схема, импорт, клиент одного часа и PostgreSQL gate реализованы,
живой автоматический импорт ещё не подтверждён; S123: поиск по индексу и UI
реализованы для ограниченного корпуса; S124 начат на одном образце;
S122/S125–S127 не выполнены**.
Подробные владельцы,
предлагаемые owned files, зависимости, acceptance и проверки находятся в
[плане полного индекса ЕИС](../../eis/search/26-eis-full-corpus-plan.md). Порядок:

1. S120 — подтвердить официальный контракт источника и разрешённый доступ;
2. S121 — инкрементальный индекс одного типа открытых аукционов 44‑ФЗ;
3. S122 — остальные подтверждённые публичные процедуры 44‑ФЗ и 223‑ФЗ;
4. S123 — поиск по индексу и объяснимый первичный отбор;
5. S124 — документы и проверка полного состава отобранных лотов;
6. S125 — полная экономика поставщика и порядок по консервативной прибыли;
7. S126 — связанная с протоколами оценка конкуренции;
8. S127 — независимая проверка охвата и регулярная эксплуатация.

По S120 получены официальные схема и альбом ТФФ 16.3, инструкция, а затем
пользователь предоставил активный токен ЕИС. `getDocsIP` на
`int.zakupki.gov.ru` подтвердил живой XSD-валидный SOAP-ответ, готовность
архива и GET ZIP с токеном. Два реальных образца 44-ФЗ — запрос котировок
№ `0303300031426000056` и электронный аукцион № `0848300054826000154` —
прошли `fcsExport.xsd` 16.3 и сверены с публичными карточками по номеру,
предмету и сроку; для аукциона также подтверждена НМЦК 182 420,00 RUB.
Повторный GET первого архива дал идентичные байты. SHA-256 и ограничения
записаны в [реестре фактов](../../research/07-research-log.md) и
[ADR-0044](../../adr/0044-eis-source-contract.md). Доступ `getDocsLE` для юрлица
остался непроверенным. Обложка основного DOCX альбома указывает «16.2»
при метке пакета 16.3; живые XML валидированы XSD самого пакета.

S121: `src/procurement/sources/eis_feed.py` разбирает ответы `getDocsIP` и
`getDocsLE`, включая оба списка подготовленных архивов, `noData` и ошибки.
Живой ответ ЕИС дал `index/createDateTime` без timezone; оно сохраняется
как `UNKNOWN_TZ` и не служит aware watermark. `eis_discovery.py` теперь
принимает реальный `<export>` из ZIP и извлекает номер, тип, версию,
публикацию, предмет, НМЦК с валютой и deadline. Живой аукцион по запросу
«бумага» дал одну карточку с проверенными полями. Профильные тесты,
Ruff и strict mypy для feed-парсера прошли. Регионально-часовой sync,
история изменений/отмен и поиск по корпусу ещё
не реализованы; UI всё ещё ограничен прежним HTML-пилотом. Одно часовое
окно `PRIZ/50/2026-09-25/17+03:00` уже дало шесть XSD-валидных XML; один
побайтно совпал с архивом по номеру. Новый `eis_feed_archive.py` извлекает
все шесть карточек независимо от поискового запроса и оставляет охват
`UNKNOWN`; профильные тесты и strict mypy прошли. Следующий шаг —
tenant-scoped индекс и идемпотентный повтор окна. Для рейтинга выгоды отдельно
потребуются действительное КП, все расходы и три сценария.

Новый срез S121: immutable tenant-scoped таблицы окон, ZIP и версий
извещений с RLS и audit; код атомарного импорта связывает официальный
`LINKS_PENDING → READY` с точным набором URL, отвергает недостающий ZIP,
конфликт версии и допускает повтор без дублей. SQL миграции сгенерирован
Alembic; затем на отдельном временном PostgreSQL 16 прошли миграция,
идемпотентный повтор окна, tenant RLS, запрет изменения и откат транзакции
при конфликте версии. Дополнительно живой архив импортирован в отдельный
временный PostgreSQL: 6 версий, 17 позиций лота, 36 ссылок на документы,
повтор без дублей. Контейнеры и тома удалены после проверок. S123: сравнение на реальных шести
карточках разделяет полное и частичное совпадение; экономическая оценка
требует расходов, привязанных к XML SHA. S124: из XML бумаги получены 500
пачек, цена 364,84 RUB, пять структурированных характеристик и шесть
ссылок. Все шесть перечисленных вложений скачаны с точным совпадением
размеров; `eis_document_sync.py` даёт `COMPLETE_LISTED_SET`, но анализ и
review остаются `UNKNOWN` из-за неподдержанных частей трёх файлов.
Автомаппер требований вернул 0 кандидатов при 70 блоках спецификации и 241
блоке проекта контракта. У DOCX заявки абсолютный путь `/word/media/` теперь
обрабатывается безопасно; само GIF остаётся неподдержанным для OCR. UI пока использует прежний
HTML-пилот, а не новый индекс.

позицию лота и выводит `STRONG | PARTIAL` с XML-локатором; на живом ZIP

регулярный индекс к UI и не подтверждает охват всей ЕИС.
Проверки этого среза: полный `pytest -q`, Ruff по репозиторию, strict mypy
парсера, web lint и production build прошли; PostgreSQL gate и отдельный
живой ZIP-прогон прошли на временном PostgreSQL 16.
