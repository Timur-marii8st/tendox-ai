# Навигация по документации

Документы разделены по роли. Если источники расходятся, учитывайте статус
документа и фиксируйте решение в ADR или в актуальном аудите.

| Роль | Источник истины | Что там находится |
|---|---|---|
| Требования продукта | [11-product-requirements.md](11-product-requirements.md) | Полное PRD, обязательные сценарии и границы продукта |
| Видение и домен | [00-vision.md](00-vision.md), [01-domain-model.md](01-domain-model.md) | Цели и целевые доменные контракты |
| Целевая архитектура | [02-architecture.md](02-architecture.md), [03-compliance-engine.md](03-compliance-engine.md), [04-economics.md](04-economics.md) | Архитектурные границы и правила движков |
| План работ | [05-roadmap.md](05-roadmap.md) | Последовательные вертикальные срезы и их гейты |
| Исторический аудит готовности | [13-partner-spec-audit.md](13-partner-spec-audit.md) | Снимок ревизии по состоянию на 2026-09-07; не заменяет live-статус |
| Актуальный план и статус | [15-implementation-plan.md](15-implementation-plan.md) | Текущий порядок срезов, критерии и незавершённая работа |
| Локальный запуск S1 | [16-local-case-workflow.md](16-local-case-workflow.md) | CLI, синтетический пример, журнал и ограничения |
| PostgreSQL и API S2 | [17-storage-api.md](17-storage-api.md) | RLS, bearer identity, миграции, bootstrap и серверный запуск |
| Реестр продуктовых агентов | [14-product-agents.md](14-product-agents.md) | Агенты, типизированные границы и уровни автономии |
| Трассировка требований | [12-requirements-traceability.md](12-requirements-traceability.md) | Связь требований с реализацией и проверками |
| Правовые и security ограничения | [06-legal-security.md](06-legal-security.md) | Источники, ограничения интеграций и безопасные границы |
| Исследования | [07-research-log.md](07-research-log.md) | Проверенные факты, гипотезы и требующие проверки сведения |
| Решения | [adr/](adr/) | Исторические ADR: контекст, решение и последствия; новые решения не переписывают старые |
| Архив | [ии.docx](ии.docx) и legacy HTML | Справочные материалы, не источник текущей готовности |

`05-roadmap.md` описывает целевую последовательность, `13-partner-spec-audit.md`
остаётся историческим снимком на 2026-09-07, а `15-implementation-plan.md`
фиксирует текущий live-статус и критерии завершения. Архитектурные документы
задают направление; код и проверки показывают фактическую реализацию. При
изменении поведения обновляйте соответствующий документ и, если меняется
архитектурное решение, добавляйте новый ADR.

Правила разработки и распределение ролей находятся в корневых
[AGENTS.md](../AGENTS.md) и [CLAUDE.md](../CLAUDE.md), а реестр продуктовых
агентов — в [14-product-agents.md](14-product-agents.md).
