# Review лимита метаданных вложений ЕИС

Дата проверки: 2026-10-03. Область: разбор сохранённого архива извещений 44-ФЗ;
скачивание документов, admission, HTTP и планировщик не менялись.

## Причина отказа

`_attachments()` отклонял извещение при наличии более 100 элементов
`attachmentInfo` с причиной `ATTACHMENT_COUNT_LIMIT`. Это лимитировало только
метаданные из уже ограниченного XML: UID, имя, заявленный размер, официальный
URL, вид документа и точный ordinal locator. Байты документов на этом этапе не
скачиваются. Поэтому лимит download worker был ошибочно применён как условие
валидности source notice.

`inspect_eis_auction_archive()` разбирает окно атомарно. Ошибка одного XML
отклоняет весь дневной архив, включая остальные корректные извещения. В
операционном наблюдении это блокировало окна региона 77: EOK за 2026-10-02 и EF
за 2026-09-30.

Байты этих двух неуспешных окон не были доступны в retained storage API во время
review: `/var/lib/eis-browser/discovery/eis-discovery.sqlite3` не содержал
артефактов, а атомарно отклонённый архив не был сохранён как `eis_feed_archives`.
Поэтому фактическое число `attachmentInfo` в live notices остаётся `UNKNOWN`.
Вывод о причине основан на сохранённом safe reason и точной ветке parser; тесты
используют только синтетические данные.

## Принятый контракт

- Parser сохраняет все metadata entries до 4096 включительно. У каждой записи
  остаются исходный UID, имя, заявленный размер, официальный URL, kind code и
  locator `.../attachmentInfo[n]`.
- 4097 и более записей дают hard failure
  `ATTACHMENT_METADATA_COUNT_LIMIT`. Тихого усечения нет: текущая persisted
  модель не имеет поля, способного честно выразить неполный attachment set.
- Лимит 4096 ограничивает число объектов parser, а существующий лимит XML 32 MiB
  независимо ограничивает входные байты. Лимиты ZIP 50 MiB, 1000 members и
  expansion 200 MiB не изменены.
- Проверки official HTTPS URL и совпадения UID, уникальности UID, имени файла,
  неотрицательного заявленного размера, unsafe XML, provenance SHA и duplicate
  notice version сохранены.
- Бюджеты document worker не входят в валидность извещения и этим изменением не
  расширялись.

## Evidence проверки

Focused regressions проверяют: 101 вложение вместе со вторым извещением в одном
архиве; включительную границу 4096; атомарный отказ всего архива на 4097; duplicate
UID после прежней сотой позиции; сохранение ordinal locator, source response SHA
и `corpus_coverage=UNKNOWN`. Live ingestion и production writes в этом review не
выполнялись.
