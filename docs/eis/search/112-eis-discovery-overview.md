## Контракт и owned files

Зависимости: существующие ответы `eis-index`, `eis-223-index`, региональный
coverage; [PRD §3.1](../../product/11-product-requirements.md),
[план полного поиска](26-eis-full-corpus-plan.md),
[граница cached-поиска](69-eis-search-deadline-scope.md).

Owned files: `web/src/app/tender-discovery/{page,indexed-search,indexed-223-search,
mixed-comparison,result-explorer}.tsx`, `web/tests/eis-discovery-overview.test.tsx`,
`web/tsconfig.discovery-tests.json`, `web/package.json`, этот документ,
тематический README и короткая запись live-плана.

Acceptance:

- Первое представление результатов — счётчики, схема способов закупки и фильтры.
- Найденные в базе и возвращённые сервером записи имеют отдельные счётчики.
- Схема и фильтры относятся только к полученным записям, а не ко всей ЕИС.
- На странице до десяти компактных строк; условия и источники раскрываются.
- FAIL/UNKNOWN видны в закрытой строке; совпадение слов не даёт технический допуск.
- Денежные строки не преобразуются в Number и не суммируются.
- Сравнение, документы, протоколы, аналоги и provenance остаются доступны.
- Регионы ручного обновления не выдаются за региональный фильтр поисковой базы.

Расширенный публичный workflow, региональный отчёт и инструменты сравнения
свёрнуты, чтобы сначала пользователь видел товарный поиск. Схема
«обзор → отбор → ТЗ → КП и экономика» объясняет последовательность, а не
обещает автоматическое завершение всех этапов.

## Проверка и оставшиеся границы

Локальные проверки: четыре Node render/filter regression tests PASS;
TypeScript/production build и scoped ESLint PASS.
Общий `scripts/check_docs.py` FAIL только на двух документах вне owned scope:
`docs/adr/0105-human-supplier-captcha.md` и
`docs/suppliers/112-human-supplier-captcha.md` пока отсутствуют в своих индексах.
Документ и индекс этого среза не дают ошибок.
Браузер: синтетические 23 записи, FAIL filter, раскрытие источника,
переход 1→2 страницы и сброс страницы при выборе способа проверены.
Desktop и 390px mobile просмотрены; горизонтального переполнения mobile нет.
Настоящий первый экран `/tender-discovery` просмотрен локально.
Временная fixture route удалена до production build. Скриншоты локального QA:
`tmp/discovery-overview/desktop.jpg`, `tmp/discovery-overview/mobile.jpg` (gitignored).
Production UI browser не проверен: доступ браузера к домену заблокирован;
это не свидетельство неработоспособности сервиса.

Последующий срез: [серверное продолжение выдачи и census](113-eis-search-continuation.md)
реализованы, проверены и установлены; прежние ограничения API ниже
относятся к установленной версии на момент первого read-only снимка.

Срез не расширяет корпус, не вводит semantic/category classification и не
выполняет полный анализ документов. Пагинация переключает только возвращённые
до 100 записей; остальные совпадения пока доступны через уточнение запроса.
При уходе со страницы результата несохранённое состояние его подробных форм
может сбрасываться; сохранённые evidence и выбор сравнения не меняются.

Следующий bounded-срез поиска: серверная пагинация с устойчивой привязкой к
снимку/сортировке и без потерь/дубликатов. Следующий срез охвата: отдельный
read-only census по закону × семейству × региону × дате с разделением
планирования, получения, NO_DATA, ошибки, отсутствующего scope и source gaps;
после сверки — адресное восстановление конкретных пропусков. До независимой
сверки никакое количество строк не становится заявлением «полная ЕИС».
