# S186 — поиск по сроку в сохранённых карточках ЕИС

Дата: 04.10.2026. Статус: выпущено на VPS; тесты, benchmark, API,
интерфейс и независимый review пройдены.
Архитектурный контракт: [ADR0068](../../adr/0068-eis-cached-search-deadline-scope.md).

## Поведение

Поиск 44-ФЗ по умолчанию оставляет последние известные версии карточек,
у которых срок подачи ещё не истёк или неизвестен. Переключатель
«Включить закупки с истёкшим сроком из сохранённой истории» возвращает
исторические карточки. Это поиск в загруженной базе, не новая загрузка ЕИС.

| Режим | Условие | Значение |
| --- | --- | --- |
| `NOT_EXPIRED_OR_UNKNOWN` | deadline NULL или deadline > единый aware now | HTTP API и UI по умолчанию |
| `ALL_CACHED` | Без фильтра срока | Исторический режим; storage default для существующих внутренних вызовов |

Фильтр применяется в SQL до загрузки и разбора карточек. Он действует
как для поисковых ключей, так и для резервного пути карточек без ключей.
Сначала выбирается последняя версия: истёкшая новая версия не позволяет
вернуть старую версию с будущим сроком. Ровно `deadline == now` — уже истёкший
срок. Время без часового пояса и неизвестный режим отклоняются до работы с БД.

Неизвестный срок сохраняется как UNKNOWN. Будущий срок не доказывает,
что подача открыта. Отмены, блокировки вариантов, источники фактов,
ранжирование и проверка условий участия работают по прежним правилам.
Полный охват и свежесть ЕИС остаются UNKNOWN.

## Счётчики и API

`GET /v1/tender-discovery/eis-index?query=бумага`
использует `NOT_EXPIRED_OR_UNKNOWN`. Для истории передать
`search_scope=ALL_CACHED`. Неизвестный scope даёт 422. Авторизация и
изоляция организации обязательны, успешный ответ содержит `Cache-Control: no-store`.

- `search_scope` — режим выполненного поиска, независимо от текущего положения переключателя.
- `total_current_notices` — последние известные карточки организации до фильтра срока.
- `excluded_expired_current_notices` — число карточек, исключённых этим режимом; в истории равно нулю.
- `inspected_current_notices`, `held_current_notices`, matched/evaluated/eligible — выбранный режим.
- planned/pending windows и source coverage — общая очередь, не уменьшаются из-за фильтра.
- `unindexed_versions` — общий остаток версий без поисковых ключей; подходящие выбранному режиму карточки проверяются резервным путём.

223-ФЗ в этом срезе не меняется. Деньги и допуск к участию не выводятся из
срока или релевантности текста.

## Измерение скорости

Один PostgreSQL REPEATABLE READ READ ONLY snapshot и один aware clock.
Прежний deployed query module загружен отдельно; сравниваются типизированные
payloads, а не идентичность классов отдельно загруженных Pydantic modules.
Проверяется весь набор совпадений до top100 и итоговый порядок с источниками.
Старый поиск после такого же deadline-фильтра должен точно совпадать с новым.

По пять прогретых запусков старого поиска и нового режима для «бумага»,
«серверное оборудование», «бумага А4 80»; порядок чередуется. Отдельные profiling
runs не входят в latency medians. Фиксируются SQL calls/time, число разобранных
карточек, размер JSON ответа, размер сериализованного входа snapshot и RSS,
наблюдаемый каждые 25 ms. RSS включает сохранённую память Python allocator;
это не измерение пика всего контейнера. Все измерения на VPS, source requests0,
DB writes0, лимиты worker CPU2/memory2GiB прежние.

снимка, не SLA поиска по полной ЕИС. Новая схема или индекс не добавлены.
