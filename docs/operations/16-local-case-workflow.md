# Локальный расчёт кейса — S1

Этот этап проверяет вручную собранные данные. Он не подключён к ЕИС,
маркетплейсам или почте и не выдаёт юридическое заключение. Проверяющий заранее
вводит результаты обязательных проверок с источниками. Для разработки используется
только явно помеченный синтетический пример поставки офисной бумаги.

## Запуск

Из корня проекта в PowerShell:

```powershell
uv sync --extra dev
uv run python -m procurement evaluate examples/paper_case.json --actor demo-operator --at 2026-09-08T12:00:00+03:00
```

Если убрать `--at`, используется текущее время. Фиксированное время нужно для
воспроизводимого примера: позднее его срок подачи и КП закономерно истекут.
Положительное решение в прошлом не подтверждает актуальность закупки сегодня.

Команда выводит JSON: решение, цвет, основания, прибыль, маржу, price floor,
идентификатор расчёта и путь к записи. Отказ или «требуется анализ» — успешный
расчёт (exit code 0), повреждённый ввод или невозможность сохранения — exit code 2.

Ожидаемый результат приведённого примера: `participate`, зелёный, прибыль
365 000 руб., отображаемая маржа 25,17%, цена остановки 1 235 000 руб.
Это результат вручную заданных синтетических условий.

## Запись расчёта

Каждый запуск создаёт новый файл в `data/evaluations/`, каталог исключён из Git.
`--audit-dir` позволяет задать другую локальную папку. Существующий файл не
перезаписывается. Запись содержит company_id, введённый actor, время фактического
запуска, момент расчёта, версию алгоритма `s1-v1`, снимок кейса, хеш входов и рекомендацию.

Это локальный журнал разработчика. Здесь ещё нет аутентификации actor,
шифрования, tenant access control или защиты записей от изменения владельцем
компьютера. Такие гарантии относятся к S2; локальную папку нельзя выдавать за
защищённый SaaS-аудит. Файлы содержат введённые данные кейса.

## Подготовка входных данных

Деньги передаются строками (`"900000.00"`) или целыми числами; дробные JSON-числа
не принимаются как денежные значения. Ставка НДС задаётся явно, не выбирается
программой по умолчанию. В примере ставка иллюстративная, не налоговая рекомендация.
Для S1 НМЦК, выручка, закупочная стоимость и финансовые лимиты вводятся на
единой сопоставимой базе без НДС. Если реальный лимит компании задан с НДС,
проверяющий должен подготовить сопоставимые значения до расчёта. Ставка поставщика
может отличаться от ставки выручки; невозмещаемый НДС включается проверяющим в
затраты. Автоматического налогового пересчёта здесь пока нет.

В каждой статье расходов нужно указать сумму, в том числе осознанный ноль.
При отсутствии статьи предварительная арифметика доступна, но положительное
решение блокируется. Список явно заданных статей сохраняется в JSON, поэтому
повторная загрузка не превращает пропущенный расход в подтверждённый ноль.

КП относится к одной компании и одной процедуре и покрывает весь комплект.
Критические условия и сроки должны быть известны. Изменение профиля, процедуры,
КП или сценариев делает старую оценку неприменимой: проверяющий повторно
проверяет изменённые данные и создаёт новую оценку их снимка.

Рейтинг служит пояснением и сортировкой. Отсутствующая обязательная проверка,
неизвестный расход, истёкшее КП или устаревшая оценка не компенсируются баллами.
Юридические и коммерческие основания сохраняются раздельно.

## Ограничения этапа

Один комплект поставки и одно КП, RUB, вручную рассчитанные расходы на единой
базе НДС. Нет оптимизации нескольких поставщиков, автоматического расчёта
налогов/логистики, cash-flow, приложений заявки, исполнителя или внешних действий.
Продажи «с полки» пока требуют отдельного анализа; наличие типов платформ
не включает автоматическую рекомендацию по ним.
