# Операционный запуск ограниченного индекса ЕИС

Статус на 2026-09-28: поддержаны **одна дата или один час, один регион,
`epNotificationEF2020` (электронный аукцион) и `epNotificationEZK2020`
(электронный запрос котировок), 44-ФЗ** через `getDocsIP`.
Полнота всей ЕИС не подтверждена. Расписание выбранных регионов 50/77 через
серверный proxy включено 2026-09-28; остальные регионы/виды не подключены.
Этот runbook не является инструкцией массовой выгрузки. Серверное развёртывание
и решение сетевого блокера описаны в [runbook сервера](28-eis-server-operations.md).

## Предусловия

1. Настроить PostgreSQL по [README](../../README.md), задать
   `DATABASE_ADMIN_URL` и выполнить `uv run alembic upgrade head`.
2. Задать runtime `DATABASE_URL` для tenant-scoped роли и установить
   Chromium: `uv run --no-sync playwright install chromium`.
3. Передать действующий `EIS_GETDOCS_IP_TOKEN` через локальный менеджер
   секретов или переменную окружения процесса. Не помещать его в URL,
   аргументы CLI, логи, документацию или Git. Для разных компаний использовать
   их собственные `company-id` и права доступа.

## Историческая дата и регулярный час

```powershell
uv run syurai-eis-sync --company-id COMPANY_ID --actor-id OPERATOR_ID --region 50 --day 2026-09-25 --exact-date --utc-offset 3
uv run syurai-eis-backfill --company-id COMPANY_ID --actor-id OPERATOR_ID --region 50 --from-day 2026-09-24 --through-day 2026-09-26 --utc-offset 3
uv run syurai-eis-backfill --company-id COMPANY_ID --actor-id WORKER_ID --region 50 --recent-days 3 --utc-offset 3
uv run syurai-eis-gaps --company-id COMPANY_ID --region 50
uv run syurai-eis-sync --company-id COMPANY_ID --actor-id OPERATOR_ID --region 50 --day 2026-09-25 --hour 17 --utc-offset 3
```

`--exact-date` предназначен для начальной загрузки прошедших дат.
Диапазонный запуск ограничен 31 завершённой датой одного региона и одного
типа; успешные даты при повторе пропускаются. `--hour` относится к
регулярному режиму и требует запуска после двухчасового отставания окна.
Для защиты локальной машины одно окно допускает не более 20 ZIP, 64 МиБ
сжатых данных суммарно и 128 МиБ по размерам распакованных XML. Превышение
даёт явную ошибку и оставляет дату незавершённой в журнале; лимит не
«обрезает» архив. Это предел одного окна, а не квота общего размера БД.
Полный корпус следует размещать во внешнем хранилище/на сервере; локальный
PostgreSQL остаётся ограниченным пилотом.
`--recent-days N` вычисляет последние N завершённых календарных дат в
заданном UTC-смещении. Для регулярной работы запускать эту одноразовую
команду ежедневно внешним планировщиком под отдельной учётной записью, не
допуская параллельных запусков для того же региона. Токен и строку БД
передавать через окружение процесса из менеджера секретов. В локальном
пилоте системное расписание и постоянная доставка секрета ещё не настроены.

Перед сетью диапазонный клиент записывает все выбранные даты в immutable
tenant-scoped журнал (`eis_sync_targets`), затем записывает каждую попытку в
`eis_sync_attempts` вместе с исходом, кодом ошибки и SHA ответа, если он
есть. `syurai-eis-gaps` показывает даты без полного checkpoint, включая
запланированные, но не запущенные после прерывания. `NO_DATA`, неготовый
архив и ошибка остаются в этом списке. Само сообщение `SYNCED` в журнале
не закрывает дату: нужен импортированный полный набор архивов. Старые окна,
созданные до миграции журнала, появятся в нём после повторного планирования;
часовой `syurai-eis-sync` пока не пишет в этот журнал.
`NO_DATA` в диапазоне не маскируется под импорт: команда продолжит другие
даты, выведет SHA ответа и завершится как `PARTIAL` с ненулевым кодом.

Успешный результат `SYNCED` означает атомарный импорт всех архивов,
сопоставленных с точным ответом READY. `SKIPPED` означает, что это окно уже
импортировано для данной компании. `NO_DATA`, `PREPARING`, `SERVICE_ERROR`
и `FAILED` возвращают ненулевой exit code и **не закрывают пробел охвата**.
Окно можно повторить после устранения причины. Список требуемых регионов и
часов регулярного режима продолжает задавать оператор.
Для запланированных дат очередь пробелов теперь хранится в PostgreSQL;
оператор продолжает определять нужные регионы и контролировать часовой режим.

Проверка результатов: открыть `/tender-discovery`, раздел «Поиск по
сохранённым XML ЕИС», ввести предмет поставки. API
`GET /v1/tender-discovery/eis-index?query=...` читает только текущие версии
из индекса компании авторизованного пользователя. Экран показывает исходный
час, XML SHA-256, позиции лота, ссылки на документы и основания совпадения.
Даже при совпадении `corpus_coverage=UNKNOWN`; НМЦК не является прибылью,
а отсутствие полного КП и затрат оставляет `economic_status=UNKNOWN`.

## Проверенная граница источника

Историческое часовое окно 2026-09-25 вернуло READY, но GET URL архива ответил
HTTP 404; checkpoint не записан. Запрос известного номера и `exactDate`
той же даты скачали ZIP с HTTP 200. Поэтому для истории используется
`exactDate`, а `oneHourInfo` остаётся для регулярного получения новых
документов. Поведение старого часового URL не объявляется нормой для всех
окон. Не считать READY без скачанного и проверенного ZIP завершённой
выгрузкой.

Ссылка из ответа READY имеет приоритет; её `compoundUid` проверяется
против исходного ответа. В локальном пилоте импортированы полные даты
24–26 сентября 2026 года, регион 50, один тип аукциона: 328 версий,
313 текущих карточек и отдельное часовое окно (6 карточек, уже входящих
в состав даты). Для новых импортов сохраняются URL ZIP и SHA ответа READY.
XML от 24 сентября (182 записи) прошли проверку XSD 16.3.
Отдельная локальная БД запускается проектом Docker Compose
`vibe-seller-eis-pilot`; её runtime URL лежит только в игнорируемом
`data/eis-pilot/database.json`, который читает `scripts/start-eis-pilot.py`.
Это ограниченный корпус, и его количество нельзя использовать как показатель
полноты всей ЕИС.
Дополнительный запуск диапазона 21–23 сентября добавил 6 ZIP и 543 версии;
на 2026-09-27 пилот содержит 7 окон, 871 версию и 796 текущих карточек.
Поиск по серверному оборудованию дал 76 совпадений, по офисной бумаге — 20;
совпадение по тексту не подтверждает пригодность закупки или прибыль.
Пилотное окно `exactDate` 2026-09-24 региона 77 добавило 5 архивов и 492
XSD-валидные версии. Общий индекс двух регионов теперь содержит 8 окон,
1363 версии и 1283 текущие карточки; найдено 103 текстовых совпадения по
серверному оборудованию и 29 по офисной бумаге. Один реальный XML был
24,3 МБ, поэтому лимит отдельного XML поднят до 32 МБ при сохранении
ограничений архива и общей распаковки. Числа не подтверждают полный охват.
После перезапуска Windows при необходимости запустить локальный контейнер
`docker start vibe-seller-eis-pilot-postgres-1`, затем локальный пилот:
`uv run --no-sync python scripts/start-eis-pilot.py` из корня проекта
(порты 3000 и 8000 должны быть свободны). Файл `database.json` содержит
локальные пароли и остаётся вне Git; не публиковать его.

## Проверка изменений

`syurai-eis-sync` и `syurai-eis-backfill` принимают
`--document-type epNotificationEF2020|epNotificationEZK2020`, по умолчанию
аукцион. Для другого типа запускать отдельную команду. Checkpoint и журнал
котировок используют суффикс `/epNotificationEZK2020`, поэтому импорт
аукционов той же даты не закрывает котировки. XML другого типа в выбранном
окне отклоняется атомарно; остальные типы пока не поддержаны. Миграция
`20260928_01` допускает котировки в БД. Откат при наличии этих данных
блокируется constraint и сохраняет записи.

Серверный пилот: 2918 версий, 2765 текущих карточек, 19 окон и 38 ZIP.
Котировки добавили 583 версии; повтор одного дня не добавил дублей.
API/UI проверяют тип, официальный URL `zk20` и статус экономики `UNKNOWN`.
Пять незакрытых `NO_DATA` видны через `syurai-eis-gaps`; ежедневный запуск
двух типов и двух регионов описан в [серверном runbook](28-eis-server-operations.md).

`tests/test_eis_feed_sync.py` проверяет корреляцию, повтор, `noData`,
ошибку и неполный архив. `tests/integration/test_eis_notice_index_pg.py`
проверяет транзакцию, tenant RLS, версии и поиск в PostgreSQL. Отдельный
игнорируемый локальный архив одного часа использовался для проверки шести
реальных XML; он не является репрезентативным корпусом.
Миграция `20260927_03` и PostgreSQL gate проверяют журнал, tenant RLS,
неизменяемость и то, что только checkpoint закрывает пропуск. Живой импорт
18 сентября региона 50 через журнал добавил 2 ZIP и 199 версий; после
него список пробелов региона пуст. Общий индекс пилота: 9 окон, 1562 версии,
1462 текущие карточки; текстовые запросы дали 113 и 34 совпадения для
серверного оборудования и офисной бумаги соответственно.
