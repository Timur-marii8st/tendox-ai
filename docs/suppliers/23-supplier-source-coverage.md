# Покрытие источников поиска производителей и поставщиков

Проверка публичных страниц: 2026-09-22. Это рабочий реестр кандидатов для
подключения, а не утверждение об исчерпывающем перечне площадок или их доле рынка.
Источники ниже названы «крупными для проверки» по их назначению и видимости,
без неподтверждённого рейтинга популярности.

## Что требует ТЗ

[Раздел 3.3](../product/11-product-requirements.md) требует искать производителей,
оптовиков, подрядчиков и допустимые предложения маркетплейсов в РФ, ЕАЭС и
разрешённых странах. Сравниваются происхождение, характеристики, цена, MOQ,
наличие, производство, оплата, доставка и гарантия. [Раздел 3.1](../product/11-product-requirements.md)
отдельно задаёт мониторинг процедур ЕИС, ЭТП и заказчиков. Это разные потоки:
поиск закупки заказчика не устанавливает производителя нужного товара.

## Порядок расширения

1. Установить канал получения данных/правила доступа для ГИСП и одного
   многокатегорийного каталога поставщиков. Для реестра ЕАЭС официальный
   публичный API уже проверен: один ограниченный POST, URL, размер и SHA-256
   ответа, отдельный статус ошибки. Источник возвращает изготовителей, но не
   коммерческие предложения и не заменяет поиск на торговых площадках.
2. Добавить независимые source attempts для двух-трёх B2B-каталогов. Частичная
   ошибка не превращается в пустую выдачу. Сопоставление и дедупликация идут
   после сохранения provenance каждого источника.
3. Включать маркетплейсы и иностранные источники только после проверки
   покупательского канала, географии/политики компании, документов, НДС и
   условий автоматизированного доступа. Исходящие запросы поставщикам —
   отдельный exact-payload approval.

Экран `/supplier-discovery` ищет по товарам и названиям компаний в двух
опубликованных коллекциях ЕАЭС. План по ТЗ выбирает ServerMall HPE Gen12
для подходящих серверных запросов, «Гравитон» — для четырёх групп,
DEPO — для серверов, Яндекс Маркет — для насосов, ноутбуков,
принтеров/МФУ. При неоднозначной или неизвестной группе неподходящий каталог
не вызывается. Выдача Маркета фильтруется по всем словам названия и ограничена
двумя страницами; переход разрешён по ссылке или проверенным данным
продолжения в прочитанной странице (S108). Это локальный поиск в части категории, не поиск
по всей площадке. Фиксированные URL страниц и правило сопоставления связаны
с exact approval текущего плана v8. Для каждой страницы сохраняются время, URL,
SHA-256 и счётчики; ошибка второй страницы оставляет первую как PARTIAL.
Отсутствие ссылки продолжения не подтверждает полноту. По ГИСП и PromPortal
дан ручной маршрут. Ошибка источника не означает ноль совпадений; соответствие
найденных карточек остаётся UNKNOWN. Ответ пока не сохраняется в кейс и
не используется для hard gate или происхождения поставляемой партии.
До коннекторов остальных
площадок широкое автоматическое покрытие остаётся `UNKNOWN`. Проверка
`robots.txt` 2026-09-21: Flagma закрывает `/search/`, Supl.biz закрывает
`?query=`, Пульс цен закрывает пути `search`, PromPortal закрывает `?q=`;
прямой автоматический поиск по этим маршрутам не подключён. Публичный sitemap
PromPortal не даёт права копировать материалы: пользовательское соглашение
площадки отдельно запрещает это без письменного разрешения. Доступ к ГИСП
с текущего хоста возвращает HTTP 403 (2026-09-21).

### Дополнение S106: браузерный путь в поиске по ТЗ

На экране документа подключены AUTO/HTTP/BROWSER. AUTO после ошибки прямого
чтения делает одну попытку browser worker только для подключённых категорий.
ServerMall и категория насосов Яндекс Маркета дали живые браузерные карточки
2026-09-22. Исправлена обработка служебных параметров Яндекса при неизменном
пути категории; её hid фиксирован. Это не site-wide поиск и не расширение
доступа к остальным площадкам. Параметры режима связаны с exact plan; компания
берётся из авторизации. [Контракт и evidence](24-browser-catalog-pilot.md#s106--браузер-в-поиске-по-тз).

### Дополнение S107: категории и границы выдачи

2026-09-22 HTTP-чтение ноутбуков и принтеров/МФУ вернуло по 8 карточек.
В запросах обязателен явный `hid`: чистый URL ноутбуков дал HTTP 200 без
товарного ItemList. Полный API-маршрут по «МФУ HP» вернул 2 совпадения;
реестр ЕАЭС в том же прогоне вернул SOURCE_ERROR. Ссылки продолжения в живых
ответах не найдены; чтение двух страниц подтверждено синтетическими тестами
HTTP и настоящего Chromium с подменёнными сетевыми ответами.
Браузер категории принтеров перешёл на `/search?hid=138608&rs=…` и был
остановлен как SOURCE_CHANGED: `/search` в разрешённый маршрут не входит.
Это не подтверждение стабильного browser-поиска новых категорий.
Подробные хеши/времена — [контракт S107](24-browser-catalog-pilot.md#s107--категория-по-запросу-и-страницы).

### Дополнение S108: продолжение по данным страницы

Парсер теперь читает hasNextPage из публичного JSON-patch каталога с проверкой
категории, номера страницы и согласованности полей. Следующая страница может
быть подтверждена без HTML-ссылки, в пределах тех же двух утверждённых URL.
Распознавание проверено на сохранённом живом ответе, двухстраничный маршрут —
синтетически в HTTP и Chromium. Контрольный live API 09:29:49 UTC после паузы
за 429 вернул SOURCE_ERROR на первой странице; увеличение реального охвата
пока не подтверждено. Новые площадки и `/search` не подключались.

### S109–S110: живые две страницы и независимый производитель

Публичные HTTP-адаптеры теперь используют уже настроенный proxy/CA маршрут
окружения; отключение — SOURCE_HTTP_TRUST_ENV=false. В S109 живой Маркет
прочитал две страницы (24 карточки), нашёл 6 совпадений «МФУ HP», остановился
по лимиту. Ранее незавершённая HTTP-проверка пагинации закрыта; browser redirect
на /search этим изменением не разрешён.

S110 добавил в plan v5 одну публичную серверную категорию «Гравитон».
Запрос «Сервер Гравитон С2242ИУ» через настоящий API проверил 40 карточек
и нашёл одну модель; ЕАЭС также ответил COMPLETED. Нерелевантные брендовые
запросы не вызывают этот источник, явный «Гравитон» исключает каталог HPE.
Каталог «Гравитона» использует HTTP во всех режимах и возвращает отдельный
результат; отказ другого источника его не стирает. Охват ограничен одной
страницей категории серверов.

S111 расширил plan v6 до четырёх категорий «Гравитона». По товарному якорю
выбирается не более одной фиксированной категории; запрос, содержащий разные
группы или известный чужой бренд, не вызывает этот источник. Категория,
исходный URL, время и хеш ответа остаются в результате. Поиск остаётся
лексическим по названиям карточек; характеристики, цены, наличие, происхождение
и допуск не подтверждаются. Остальные категории и площадки этим срезом не охвачены.

S112 добавил независимый каталог серверов DEPO в plan v7. Запросы с явным
чужим брендом не направляются в него; DEPO также исключён из HPE/«Гравитона».
Результат имеет отдельный статус ошибки, URL страницы, время, SHA-256 и индекс
карточки. Чтение ограничено одной публичной страницей, названиями и ссылками;
цены «по запросу» не интерпретируются как числовое предложение.

S113 добавил в plan v8 одну категорию B2B-предложений Supl.biz. Только режимы
AUTO/BROWSER включают этот браузерный источник для запросов о насосах; HTTP
не запускает браузер. Адрес категории фиксирован, `/proposals/search/` и API
не используются. DOM содержит название/URL товара и показанное имя/URL
продавца; они остаются заявлением площадки, не подтверждением производителя,
цены, наличия или соответствия. Охват — одна страница без утверждения полноты;
чужие товары внутри категории отбрасываются лексическим фильтром.
