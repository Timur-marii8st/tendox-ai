браузерной передачи: браузер загружает ресурсы страницы, поэтому старое
подтверждение одного HTTP GET к нему неприменимо.

## Запуск

Из корня репозитория (PowerShell):

```powershell
uv sync --extra dev --extra browser --inexact
uv run --no-sync playwright install chromium
uv run --no-sync python scripts/preview-browser-catalog.py --company-id pilot --site servermall --query "DL360 Gen12" --headed
```

`--headed` показывает браузер; без него он работает без окна. Для установленного
Chrome/Edge доступны `--channel chrome` и `--channel msedge`. У каждого движка
отдельный профиль. Движение курсора и прокрутка включены по умолчанию;
`--no-motion` отключает их для диагностики. Код возврата: 0 — COMPLETED,
2 — источник не дал подтверждённого результата. `COOLDOWN` содержит `retry_at`;
ранний повтор не открывает браузер. CLI печатает JSON в stdout.

Второй поддержанный preview:

```powershell
uv run --no-sync python scripts/preview-browser-catalog.py --company-id pilot --site yandex_business --query "Насос центробежный" --headed
```

ServerMall ограничен категорией HPE Gen12, Яндекс выбирает категорию насосов,
ноутбуков или принтеров/МФУ по запросу. В обоих каталогах фильтруются названия.
Произвольные URL или площадки CLI не принимает. Этот же browser adapter
доступен в поиске по документу на `/supplier-discovery`; живые ограничения
новых категорий описаны в S107 ниже.

## Что реализовано и какие ограничения остаются

S113 добавил третий browser site: одну фиксированную
[категорию промышленных насосов Supl.biz](https://supl.biz/promyishlennyie-nasosyi-category4240/).
Он запускается в AUTO/BROWSER для насосного товарного якоря, но не в HTTP.
Парсер принимает только `Product` с официальной ссылкой предложения и
профиля показанного продавца; цена и роль изготовителя не подтверждаются.
Охват — одна страница, 40 карточек в живом прогоне. Общий поиск Supl.biz
по `proposals/search` закрыт и не вызывается.

- Настоящий Chromium/Chrome/Edge исполняет JavaScript. Persistent profile
  сохраняет cookies/local storage между запусками; имя каталога — SHA-256
  company_id, далее site и channel. Профиль обычного пользователя не открывается.
- Плавная кривая курсора с ускорением и торможением, небольшие порции прокрутки
  и переменные паузы. Это модель UI-взаимодействия, не доказательство того,
  что антибот посчитает посетителя человеком. Клики по кнопкам покупки,
  подтверждениям и формам не выполняются.
- Ожидание `domcontentloaded`, затем валидной структурированной выдачи в двух
  последовательных наблюдениях. Отсутствующий JSON-LD даёт SOURCE_CHANGED.
  Пустое совпадение допустимо только после успешного разбора самого каталога.
- 55 секунд на работу браузера плюс завершение процесса, до 12 секунд на
  готовность схемы, DOM до 3 МиБ (ServerMall имеет свой лимит 2 МиБ).
  Это лимит DOM и времени, не лимит всего сетевого трафика ресурсов страницы.
- Один процесс на company/site; пауза минимум 60 секунд между началами
  запусков. При отказе — минимум 15 минут с учётом большего Retry-After.
  Самостоятельных повторов нет. После аварийного завершения `preview.lock`
  может остаться: удалять только после проверки, что этот профиль уже не занят.
- 403/451, CAPTCHA, 429, вход в аккаунт, неожиданный redirect, timeout и
  изменённая схема дают отдельные причины. Полный текст исключения, cookies,
  HTML и browser trace в отчёт не попадают. DOM обрабатывается в памяти;
  SHA-256 относится к DOM после JavaScript, а не к исходному HTTP-ответу.
- Профили под `data/browser-profiles/` исключены существующим `.gitignore`.
  Они содержат локальные секреты и не предназначены для общего доступа или
  резервного копирования в публичное хранилище. CLI — однопользовательский
  инструмент, а не граница авторизации между арендаторами сервера.

Fingerprint, заголовки и TLS-проверка браузера не подменяются, CAPTCHA не
решается, IP не меняется при отказе. Автоматическое широкое покрытие площадок
этот срез не добавляет.

## S106 — браузер в поиске по ТЗ

Владелец: Codex. Owned files: `sources/browser_catalog.py`,
`sources/browser_worker.py`, `sources/document_search_plan.py`, `api/app.py`,
`web/src/lib/procurement-api.ts`, `web/src/app/supplier-discovery/`,
`tests/test_browser_catalog.py`, `tests/test_browser_worker.py`,
`tests/test_document_supplier_search.py`, `.env.example`, `README.md`, этот
документ, `docs/suppliers/23-supplier-source-coverage.md`, `docs/15-implementation-plan.md`.
Зависимости: S105 и exact-plan маршрут S102–S104.

Экран документа предлагает три режима:

- AUTO — прямое чтение; только SOURCE_ERROR каталога запускает одну браузерную
  попытку этого источника. Успех с нулём совпадений не запускает браузер.
- HTTP — прямое чтение без браузера.
- BROWSER — каталоги сразу открываются браузером, без лишнего HTTP-запроса.
  Реестр ЕАЭС во всех режимах продолжает использовать свой API.

GET плана принимает `mode`, POST запуска принимает тот же `mode` вместе с
`plan_sha256` и существующим `approve_exact_payload`. План v2 связывает
режим, transport каждого источника, загрузку ресурсов страницы и версию
браузерной политики. Изменение режима со старым digest даёт 409 до сети.
Browser company_id поступает только из проверенного principal, auditor
запускать поиск не может. GET плана не запускает браузер.

Ответ сохраняет исходные HTTP attempts и отдельный массив `browser_attempts`;
в BROWSER прямые каталоги равны null. Ошибка браузера не стирает другие
источники. UI показывает кандидатов UNKNOWN, блокировку, cooldown, занятый
профиль/worker, отсутствие Chromium, источник/время/SHA-256. После смены режима
старый результат очищается. Timeout web-клиента увеличен с 35 до 90 секунд.

Worker использует отдельный поток/event loop; Windows Proactor поддерживает
subprocess Playwright независимо от loop ASGI-сервера. Максимум два браузера
на процесс API, без неограниченной очереди: WORKER_BUSY возвращается сразу.
Ожидание общего thread executor и завершение браузера могут добавить время к
55-секундному бюджету. Для нескольких серверов этот локальный лимит не является
распределённым ограничителем нагрузки.

Server profiles: `BROWSER_PROFILE_ROOT` (по умолчанию
`data/server-browser-profiles`); они отделены от профилей CLI. Backend требует
extra `browser` и установленный Chromium. Прокси перед API должен допускать
запросы длительностью не менее 90 секунд.

## S107 — категория по запросу и страницы

План `supplier-search-plan-v3` фиксирует точные адреса до двух страниц,
правило `TITLE_TERMS_V1` и browser policy v3. ЕАЭС остаётся API-источником.
ServerMall включается для серверных запросов в пределах HPE Gen12 (1 страница),
Яндекс — для одной распознанной группы: насосы, ноутбуки, принтеры/МФУ.
Неоднозначная/неизвестная группа не запускает произвольный каталог.

Чтение Маркета использует фиксированный `hid` уже на первой странице.
Следующая страница читается только при обнаружении разрешённой ссылки;
выполняется заранее утверждённый URL, а не произвольный адрес из HTML.
HTTPS-хост, путь, hid и номер страницы проверяются, дубли параметров запрещены.
Допустим служебный rs, его значение не возвращается пользователю.
Между страницами пауза 1 с, потолок 2 страницы/100 карточек на страницу.
Браузер делит общий бюджет между страницами с резервом запуска/закрытия.

Фильтр требует все токены запроса в названии, без совпадений по части номера
модели. Нормализуются только известные формы слов насос/ноутбук/принтер.
Синонимы, перевод, характеристики и статус изготовителя не выводятся из названия.
Повторные URL дедуплицируются с сохранением первого provenance. Каждый
кандидат Маркета и браузера содержит страницу, номер и SHA-256. Отдельно
возвращаются время, статус, число прочитанных/совпавших карточек каждой страницы.
Ошибка продолжения или повтор той же страницы даёт PARTIAL, сохраняя ранее
полученные карточки. Повторная browser-попытка после HTTP PARTIAL не запускается.
NO_NEXT_LINK означает отсутствие найденной ссылки, не конец всего каталога.

## S108 — продолжение из состояния публичной страницы

HTTP-ответ Маркета содержит не только JSON-LD с товарами: в
`noframes[data-apiary=patch]` опубликован JSON
`collections.visibleSearchResult` с hids, page, pageCount, itemsPerPage,
hasNextPage и привязкой searchResultIds к текущей странице. В сохранённом
ответе принтеров от 2026-09-22T09:14:15Z указаны hid=138608, page=1,
pageCount=30, hasNextPage=true при отсутствии ссылки «далее».
SHA-256: `823fb22a6b6653bb1b779e4b8a9c5991260a172570664aa8f806abad8407c181`.

Парсер читает JSON как данные, без выполнения JavaScript. Пустая начальная
коллекция допустима, но не подтверждает продолжение. Должна быть ровно одна
непустая запись правильного entity/id; категория, номер страницы, currentPageIds
и searchResultIds согласованы. Числовые значения проверяются строго (boolean
не становится числом), hasNextPage — boolean, согласованный с pageCount.
Дубли ключей, противоречащие состояния, чужая категория, неверный номер,
повреждённый JSON или конфликт со ссылкой дают PAGINATION_STATE_INVALID.
Товары такой страницы не принимаются; ранее прочитанная страница остаётся PARTIAL.

Переход выполняется по заранее утверждённому адресу категории; внешнее состояние
разрешает только следующий номер и не задаёт URL, API-метод или количество
запросов. Предел остаётся 2 страницы. Движок возвращает основание продолжения
LINK / PAGE_STATE / LINK_AND_PAGE_STATE и локатор в HTML вместе с хешем страницы.
NO_NEXT_EVIDENCE означает отсутствие подтверждения; END_REPORTED — заявление
источника об окончании данной выдачи, не доказательство полноты всего каталога.

План `supplier-search-plan-v4` включает `CATEGORY_LINK_OR_STATE_V1`, точные
адреса и browser policy v4. Старый digest или изменение pagination_policy
не допускают запуск. UI показывает основание перехода на следующую страницу.
Навигация браузера на `/search` по-прежнему отклоняется; этот срез не расширяет
разрешённые пути и не исправляет серверный redirect новых категорий.

Проверки S108: **1066 passed, 104 skipped** (opt-in PostgreSQL/OCR),
**9 doctest passed**; Ruff, mypy (22 файла), lock, web lint/build прошли.
Настоящий Chromium с синтетическими ответами проверил две страницы без
ссылки и PARTIAL при неверном номере страницы 2. Production UI проверен
