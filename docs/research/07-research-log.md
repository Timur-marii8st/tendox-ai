# 07. Реестр фактов — со статусом проверки

Правило из [CLAUDE.md](../../CLAUDE.md): непроверенный факт **нельзя** использовать
как основание архитектурного решения.

| Статус | Значение |
|---|---|
| `ПРОВЕРЕНО` | Мы сами открыли первичный источник, дата проверки указана |
| `ТРЕБУЕТ ПРОВЕРКИ` | Взято из внешнего аналитического отчёта, первично не подтверждено |
| `ГИПОТЕЗА` | Наше предположение, требует валидации рынком |

## Важное предупреждение

Исторический блок ниже происходит из предварительного AI-ресёрча, выполненного до старта
проекта. **Его пункты не подтверждены первичным источником.** Новые проверки
датируются отдельно в конце документа.
Отчёт содержал утверждения с датами 2025–2026 гг. и ссылками, которые необходимо
открыть и перепроверить руками, включая: наличие и условия API площадок,
даты запуска ИИ-ассистентов, действующие тарифы конкурентов, рыночные оценки.

Ошибка здесь дорогая: коннектор к несуществующему или платному-по-другому тарифу
API — это выброшенный спринт, а неверная оценка рынка — неверная цена продукта.

### Проверка источников для первого коннектора — 2026-09-19

**ЕАТ, только публичный классификатор.** [Документация ЕАТ](https://berezka-tender.ru/documentation.html)
ссылается на [краткую инструкцию по интеграции, версия 2.37 от 02.03.2023](https://berezka-tender.ru/src/files/%D0%9A%D1%80%D0%B0%D1%82%D0%BA%D0%B0%D1%8F_%D0%B8%D0%BD%D1%81%D1%82%D1%80%D1%83%D0%BA%D1%86%D0%B8%D1%8F_%D0%B8%D0%BD%D1%82%D0%B5%D0%B3%D1%80%D0%B0%D1%86%D0%B8%D1%8F_%D0%95%D0%90%D0%A2_%D1%81_%D0%98%D0%A1.pdf).
Она указывает публичный ZIP классификатора и отдельно методы получения закупочных
сессий. Для методов поставщика инструкция описывает регистрацию и токен из ЛК;
её возраст не позволяет считать текущие адреса и полномочия подтверждёнными.
Живой `GET` публичного `eatCategorySet.zip` вернул HTTP 200 и 403 203 байта.
`python -m procurement.sources.eat_classifier` проверил ZIP/XML, прочитал
12 825 категорий (10 479 активных, 2 346 помечены удалёнными) и записал
SHA-256 точных байтов
`3d1f2ad92d28b3761dd5ab7830b2d2742a436503cace79cb597fd70f021e81d5`.
Это доказательство доступности и разбора **классификатора**, не поиска закупок,
производителей, наличия товара или действующих КП. Получение списка сессий,
деталей и условий использования методов с токеном остаётся `UNKNOWN` до
актуальной документации и разрешённого тестового доступа.

**ЕИС.** [Официальное сообщение ГИС ЕИС](https://t.me/gis_eiszakupki/2036)
сообщает о переходе машиночитаемых данных с FTP на сервисы отдачи с
регистрацией. Из этого не следует, что произвольный посетитель может читать
сервис программно. Актуальный Альбом ТФФ, инструкция, разрешённый токен и
проверка одного ответа пока отсутствуют в этом исследовании; возможность
получать конкретные поля извещения и вложения через нужный метод — `UNKNOWN`.
Старые адреса сервисов не принимаются как готовый контракт.

Дополнительная read-only проверка 2026-09-19: публичная главная страница
ЕИС ответила `200`, но прямые GET нескольких найденных номеров извещений
повторно дали `404` (один запрос карточки кратковременно ответил `200`, без
сохранённого и проверенного содержимого). Анонимная сессия главной страницы
не изменила результат. Поэтому ни одно извещение и ни одно вложение из ЕИС
в этом срезе не принято как source evidence; статус получения одной закупки
остаётся `UNKNOWN`. Ответы HTTP сами по себе не доказывают наличие или
отсутствие закупки либо право использовать нестабильный HTML как API.

Проверка следующего шага: получить актуальный контракт сервиса ЕИС и
предоставленный владельцем доступ, выполнить один ограниченный read-only запрос
на конкретную процедуру, сверить номер, статус/срок, список вложений и SHA-256
полученных bytes. Если доступ недоступен, ручной импорт документов с явной ролью
остаётся рабочим пилотным входом, а покрытие автоматического мониторинга —
`UNKNOWN`.

## Очередь проверки

1. Открыть документацию API B2B-Center, ЕАТ, Bidzaar → зафиксировать реальные
   методы, условия доступа, зависимость от тарифа, позицию по автоматизации.
2. Проверить актуальные тарифы KAPI, Snab.online, Pusk.app → определить ценовой
   коридор.
3. Подтвердить механику подписи CryptoPro на стороне клиента → это основание
   ADR-0001.
4. Подтвердить нормативные требования по КЭП/МЧД у юриста.
5. Найти первичный источник рыночных оценок (Data Insight) и проверить методику.
6. 30–50 интервью с ICP → willingness-to-pay, реальная длительность обработки ТЗ.
7. Получить юридическое заключение по актуальной редакции ПП РФ №1875 и вести
   машиночитаемые перечни как versioned ruleset, а не статические константы.

По каждому подтверждённому пункту статус меняется на `ПРОВЕРЕНО` с датой и прямой
ссылкой на первичный источник.
