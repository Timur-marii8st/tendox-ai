# Персональный профиль и сравнение карточек из поиска

2026-10-15. Владелец root. Срез продолжает установленную интеграцию
[профиля и поиска](10-profile-search-comparison-integration.md).

## Пользовательский путь

Персональный OPERATOR входит на `/company-profile`, заполняет профиль,
сохраняет и выбирает точную версию. Ссылка ведёт на `/tender-discovery`:
кнопки карточек добавляют 2–5 закупок 44/223 в общую корзину. Новый запрос
не очищает выбор. «Сравнить с профилем моей компании» показывает таблицу
исходных цен/сроков/способов, проверенных блокеров и недостающих сведений.
Новая версия профиля выбирается явно; старый выбор не меняется автоматически.

В рабочей компании по указанию пользователя создаётся пустой профиль:
27 UNKNOWN, без выдуманных реквизитов. Персональный ключ выдаётся приватным
локальным файлом; в промпты, журналы и Git секрет не попадает. Существующая
HttpOnly/Secure/SameSite=Strict сессия действует час. Роль OWNER не добавляется:
критические финансовые настройки и разрешения остаются заблокированными.

## Контракт

`POST /v1/procurement-comparison/notices` принимает `selection_id`,
`profile_ref(version,snapshot_sha256)` и 2–5 разных exact XML refs
`(law,purchase_number,version_number,notice_xml_sha256)`. Tenant и actor
берутся из аутентификации. AUDITOR не запускает сравнение. Недоступные
версии возвращают 404, несовместимые ссылки/хеши — 409.

Сервер переиспользует существующий `get_mixed_comparison` и проверенные
immutable readers профиля. XML-карточки не становятся полными ProcurementCase:
неизвестный timezone, НДС, требования и доставка не подменяются значениями.
Данные всех карточек читаются одним consistent-read снимком; immutable
профиль и выбор проверяются по точным ссылкам и digest.

Ответ `selected-profile-notice-comparison-v1` содержит выбранный профиль,
exact ссылки, входной digest, source comparison с provenance и checks.
Подтверждённые блокеры сохраняют FAIL; остальные условия остаются UNKNOWN.
Прибыль, допуск и проверенное соответствие деятельности не выводятся из
совпадения текста. Цены лотов не складываются и не объявляются суммами без НДС.
Отчёт EPHEMERAL; сохранения истории отчётов в этом срезе нет.

Персональная сессия используется поисковыми API вместо общего pilot-ключа;
в discovery доступны только явно перечисленные cached GET и три read-only
comparison POST. Live-поиск, source jobs и browser actions ей не разрешаются;
ошибка персонального доступа не приводит к откату на чужой tenant. Обычный
поиск не ставит обновление источника в очередь без отмеченного флажка.

## Границы проверки и выпуска

Owned: notice comparison DTO/router и bounded mixed limits, поисковая корзина,
личный auth routing, ссылки профиля, целевые unit/PG/Node проверки. Нет новой
миграции, изменения ресурсов или загрузчиков. Production выпуск и проверка
реального tenant фиксируются отдельно в приватном evidence
`tmp/improvement-program/m2/company-search-workflow-20261015-v1`.
До live acceptance этот документ описывает реализованный кандидат.
