# Экономика закупки

## Полная себестоимость

```text
all_in = goods_or_production
       + packaging
       + inbound_logistics + customer_delivery
       + loading_unloading + storage
       + installation_commissioning
       + payroll_travel + subcontracting
       + insurance + platform_fees
       + bank_fees + guarantee_cost
       + financing_cost + taxes
       + certification + warranty
       + risk_reserve + penalty_reserve + other

profit = contract_revenue - all_in
margin = profit / contract_revenue
```

НДС хранится отдельной ставкой и налоговая модель задаётся профилем компании.
Система не угадывает режим налогообложения и не считает обеспечение расходом,
если это возвратное замораживание денег: отдельно учитываются cash lock,
стоимость финансирования и стоимость независимой гарантии.

## Три обязательных сценария

| Сценарий | Назначение |
|---|---|
| `base` | подтверждённые текущие цены без негативных отклонений |
| `realistic` | наиболее вероятные цена торгов, срок и расходы |
| `conservative` | допустимые неблагоприятные отклонения и резервы |

У каждого сценария есть явные допущения. Итоговая рекомендация сравнивает лимиты
компании с `realistic`; `conservative` показывает устойчивость сделки.

## Логистика

Расчёт идёт по каждому плечу и адресу: от производителя до склада (если есть),
от склада/производителя до заказчика, разгрузка, подъём, монтаж и вывоз упаковки.
Топология `single_city`, `multi_city_one_region`, `multi_region` влияет на цену,
срок и резерв. Условие «доставка за счёт поставщика» подтверждается КП, а не
предполагается.

## Кассовый разрыв

```text
financing_cost = financed_amount × annual_rate × cash_gap_days / 365
```

График включает аванс поставщику, обеспечение, оплату логистики, приёмку,
отсрочку заказчика и прогнозную дату поступления денег.

## Цена остановки

При заданной минимальной допустимой марже `m`:

```text
minimum_bid_price = ceil_to_kopeck(max(
    realistic_all_in / (1 - m),
    realistic_all_in + min_expected_profit,
    min_contract_amount
))
```

Ставка ниже этого значения блокируется. Пересчёт возможен только после изменения
подтверждённого расхода или политики человеком.

Это формула для фиксированных расходов на единой базе НДС. Для расходов,
зависящих от цены (налоги, комиссии), нужен пересчёт при каждой ставке.
Функция recommendation не является исполнителем торгов и сама ставки не блокирует.

## Текущие ограничения реализации

`CostBreakdown` суммирует статьи и хранит `specified_cost_fields`: значение по
умолчанию `0` является provisional и не означает подтверждённый нулевой расход.
Явно заданные нули считаются подтверждёнными, а список заданных статей
сохраняется после JSON roundtrip. `CostBreakdown.is_complete` становится
истинным только когда указаны все статьи расходов.

`DealEconomics.nds_rate` по умолчанию равен `None`; система не подставляет
ставку НДС. `DealEconomics.is_complete` требует полной себестоимости и явно
заданной ставки. `ScenarioSet.is_complete` требует завершённую экономику для
всех трёх сценариев: `base`, `realistic` и `conservative`.

Остаются явный режим/ставка на дату операции, денежный график и отдельные
плечи доставки. До этого модель нельзя считать полной автоматической
экономикой из ТЗ.

## Прогноз-факт

После исполнения каждая статья получает actual value и отклонение. Эти данные
калибруют логистику и резервы, но не изменяют финансовые hard gates автоматически.
