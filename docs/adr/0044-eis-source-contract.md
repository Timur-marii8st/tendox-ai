# ADR-0044: официальный сервис отдачи ЕИС как источник индекса

Дата: 2026-09-27  
Статус: Accepted for `getDocsIP` pilot; полнота корпуса и `getDocsLE` не проверены

## Контекст и проверенные источники

Публичный HTML-поиск S116–S119 показывает только ограниченную выдачу. Он не даёт
доказательства полноты реестра, истории версий и отмен. Для поиска по корпусу
нужен машиночитаемый канал.

Официальный [раздел технической документации ЕИС](https://zakupki.gov.ru/epz/main/public/document/view.html?searchString=&sectionId=432&strictEqual=false)
на 2026-09-27 публикует «Интеграционные схемы ЕИС версии 16.3»
([ZIP, id 44404](https://zakupki.gov.ru/epz/main/public/download/downloadDocument.html?id=44404),
SHA-256 `4313b235fcfbce1e32a610cdef1f68449d23de617c15fd7487bad8cb933d86d7`)
и «Альбом ТФФ ЕИС версии 16.3»
([ZIP, id 44403](https://zakupki.gov.ru/epz/main/public/download/downloadDocument.html?id=44403),
SHA-256 `3002034fad43f72dfccb5c8a3a0fde9636abac8a0f2d33cd6df2e8d97977afc6`).
Обе записи датированы 19.09.2026. Доступна также официальная
[инструкция для физических и юридических лиц](https://zakupki.gov.ru/epz/main/public/download/downloadDocument.html?id=41500)
(PDF, 2025, SHA-256 `b352339714156eb132c60143848205489d963a907f86f36c8718a6e9b1ab62d7`).
Все три файла получены с официального сайта и проверены по локальному SHA-256.
Внутри основного DOCX альбома обложка всё ещё указывает версию **16.2** при
названии записи и архива 16.3; это расхождение требует сверки по XSD и живому
ответу, а не молчаливого принятия номера версии.

Альбом ТФФ, разделы 2.9.17–2.9.19 и приложение 17, и XSD
`GetDocsWS/GetDocsLegalEntity/getDocsLE-ws-api.xsd` описывают сервисы
`getDocsIP` и `getDocsLE`. Для юрлица требуется саморегистрация через ЕСИА
в кабинете потребителя машиночитаемых данных и двусторонний TLS с
зарегистрированным сертификатом. Сервис отдаёт только публичные документы
44-ФЗ и 223-ФЗ. Предел `getDocsLE`: 280 запросов в минуту, 20 000 в час;
при превышении ошибка 13. Для ИП/физлица `getDocsIP` требует токен и имеет
предел 90 в минуту, 4 000 в час. Это документированные потолки, а не
проектный темп: наш планировщик должен оставить запас и учитывать ответы.

## Решение

Текущий пилот использует подтверждённый токен `getDocsIP` физлица/ИП.
Для отдельного подключения юрлица потребуется `getDocsLE` с зарегистрированным
сертификатом и двусторонним TLS; этот путь ещё не проверен. Запросы
`getDocsByOrgRegionRequest` разбивать по региону КЛАДР,
подсистеме, одному типу документа и дате/часу; `getDocsByReestrNumberRequest`
использовать для сверки конкретного номера. Для первого среза 44-ФЗ —
подсистема `PRIZ`, публичный тип `epNotificationEF2020` (электронный аукцион).
Дополнение от 28.09.2026: после проверки официального XML/XSD и живого
импорта поддержан `epNotificationEZK2020` (электронный запрос котировок).
Тип выбирается явно; XML проверяется против выбранного типа, checkpoint
котировок имеет отдельный ключ. Это не расширяет утверждение о полноте
на остальные процедуры, отмены или 223-ФЗ.
Отмены `epNotificationCancel` и `epNotificationCancelFailure` обязательны для
корректной текущей проекции. `PRIZP` с протоколами об участниках в первый
индекс не включать. Для 223-ФЗ планируемая подсистема извещений — `RI223`;
точные разрешённые типы брать из `nsiDocumentTypes223`, а для 44-ФЗ — из
`nsiDocumentTypes`, только при `isDistributedPublicly=true`. Перечень из
инструкции 2025 года служит подсказкой для исследования, но не реестром
действующих типов.

XSD 16.3 поддерживает `exactDate` с часовым поясом и `oneHourInfo`. Для
`oneHourInfo` начало окна должно отставать от текущего времени более чем на
два часа; ЕИС рекомендует разнести регулярные вызовы по случайным минуте и
секунде. После ответа со ссылками необходимо опрашивать
`getPreparedPartRequest` по `docRequestUid` до
`isPreparationCompleted=true`; альбом описывает интервал 10 секунд. Ссылки
скачивать только после готовности, не считать выданный URL полученными
байтами. В ответе возможны `archiveUrl` (XSD: максимум 1000), `noData` и
`errorInfo`; эти ветви имеют разные статусы загрузки. Упоминание `noData`
относится к одному точному окну, не к отсутствию закупок во всей ЕИС.
`getPreparedPartResponse` может перечислять готовые файлы в
`preparedNotDownloadPartInfo` до первого скачивания и в `preparedPartInfo`
после него. Текущий токен передаётся в SOAP Header как
`individualPerson_token` и в заголовке GET архива; его значение не хранится
в исходниках, документации или отчётах. Живой ответ ЕИС вернул
`index/createDateTime` **без смещения часового пояса**. Это значение
сохраняется как raw/`UNKNOWN_TZ` и не используется как aware watermark.

Хранить исходные архивы и XML неизменяемыми с URL, SHA-256, временем получения,
версией схемы/парсера, координатами окна, номером и версией записи.
Checkpoint, запросы, документы, проекции и audit events — tenant-scoped.
Повтор должен быть идемпотентным. Состояние охвата может стать подтверждённым
только после проверки всех окон, готовности и скачивания всех архивов,
разбора всех записей и независимой сверки; при лимите/ошибке/неизвестном
числе архивов остаётся `PARTIAL/UNKNOWN`. Максимум 1000 ссылок в XSD не
является доказательством отсутствия усечения. Пользовательский поиск должен
показывать границы проиндексированного корпуса.

## Живой proof of access и открытые границы

Пользователь показал активный токен в кабинете ЕИС 2026-09-27. Разрешённый
`getDocsIP` proof выполнен через `https://int.zakupki.gov.ru`: WSDL открылся
с HTTP 200, XSD-валидный SOAP-запрос по известному номеру вернул ссылку,
`getPreparedPartRequest` подтвердил готовность, GET с тем же токеном отдал
ZIP. WSDL из пакета 16.3 указывает `int44.zakupki.gov.ru`, но этот адрес
не открылся в текущей среде; рабочий адрес совпал с инструкцией ЕИС.
Прямой Python HTTP-транспорт тоже завершился до ответа сервиса, поэтому
пилотный доступ проверен через Chromium. Это наблюдение среды, не вывод
о доступности адресов для других установок.

Для электронного аукциона 44-ФЗ № `0848300054826000154` получен архив
13 796 байт, SHA-256
`22fd4e02e18391ad905237de2059c5525c2b91c0f27305065237601ee21545d6`.
XML `epNotificationEF2020` внутри имеет SHA-256
`e9739ee3ee57df166b0f9265282e88208461708cfb542d62b690ea18c9c33907`,
проходит `fcsExport.xsd` 16.3 и содержит версию 1, предмет «Поставка бумаги
для офисной техники», 182 420,00 RUB и срок 05.10.2026 10:00 +03:00.
[Публичная карточка](https://zakupki.gov.ru/epz/order/notice/ea20/view/common-info.html?regNumber=0848300054826000154)
(HTML SHA-256 `3bafc26f2cc196fd313803518a0a3e880b57dfc9a09768c0aa225e66ff9db4dc`)
подтвердила номер, предмет, цену и срок. Отдельно получен образец запроса
котировок № `0303300031426000056`; повторный GET его ZIP дал идентичные
байты (SHA-256
`f23ba64e491ae7eecc3cbcc2f50e68191b9f48bface7c6d3d78fa2a58781e5d4`).

Ограниченный `getDocsByOrgRegionRequest` для `PRIZ`, региона 50, документа
`epNotificationEF2020` и часа 2026-09-25 17:00 +03:00 вернул один ZIP
90 729 байт (SHA-256
`ca67ffd1b16abf32f4583b7322f8d5d60744566f26b1735abb7bba6675181ab7`).
Все шесть XML внутри прошли `fcsExport.xsd` 16.3. Извещение
№ `0848300054826000154` совпало по SHA-256 XML с отдельным запросом по
номеру; одно из шести имеет версию 2. Типизированный разбор сохраняет все
шесть карточек до поисковой фильтрации. Эти наблюдения не подтверждают
полный региональный или исторический охват.

Открыты полнота выдачи по окнам, наличие независимого счётчика/манифеста,
все типы 44-ФЗ/223-ФЗ, отмены и связь XML с приложениями каждого типа.
Доступ `getDocsLE` также не проверен. Пока эти условия не выполнены,
нельзя утверждать, что индекс содержит всю ЕИС, или переводить ошибку
сервиса в ноль найденных закупок.

## Последствия

Публичный HTML-поиск остаётся каналом независимой сверки. Он не замещает
официальный индекс. S121 перешёл к ограниченному запросу по региону, типу и
часу; далее нужен tenant-scoped индекс с журналом неполных окон. Один
успешный часовой архив не подтверждает охват.
