# ADR-0098: независимая проверка выбранной таблицы ЕИС

Дата: 2026-10-06. Статус: принято для S228; реализовано и установлено.

## Контекст

S227 показывает исходные ячейки рядом с карточкой товара. Совпадение названий
не устанавливает нормативность документа, обязательность и интерпретацию.
Ранее созданный workflow reviewed_requirements требует зарегистрированного
полного документа кейса; частичная сохранённая таблица ЕИС не заменяет его.

## Решение

Отдельный bounded adapter сохраняет immutable exact proposal и независимое
решение COMPLETENESS_REVIEWER. Обе записи tenant-scoped, source0, с audit.
Каждая исходная строка сохранена. Исполняется только закрытая грамматика
формата бумаги; числовые units, допуски и сортность пока UNKNOWN.
Повторное чтение проверяет актуальность исходных evidence. Изменённый snapshot
не переиспользует решение. Источники и результат связываются digest.

## Последствия

Можно проверять одну доказуемую характеристику без ложного полного допуска.
Настоящее решение требует независимого пользователя. Нет выдачи новой роли
или создания фиктивного reviewer ради теста на production. Полнота ТЗ и
PARTICIPATE не повышаются. Роли юридических действий не меняются.

## Альтернативы

Автоматически считать публичную таблицу approved или зарегистрировать фиктивный
полный документ — нарушает границы полноты и независимости. Не принято.

Write lease берётся до начала REPEATABLE READ snapshot; ожидание в уже
начавшейся транзакции запрещено. FK product_run_id указывает на S226 report ID
из preview.product.run_id; S225 request.product_run_id остаётся исходным
идентификатором каталога. Обе JSON CHECK обёрнуты целиком в IS TRUE.
