# ADR-0001. Cloud brain + local agent вместо чистого SaaS

**Статус:** принято · **Дата:** 2026-08-30

## Контекст

Продукт должен выполнять действия от имени компании-поставщика на электронных
торговых площадках. Часть площадок требует усиленную электронную подпись, а
подпись в российском контуре формируется локальным криптопровайдером на стороне
пользователя. Кроме того, клиент не готов отдавать пароли от всех ЭТП внешнему
сервису, а у ряда площадок публичного API для нужных действий может не быть.

Утверждение о клиентской механике подписи пока имеет статус `ТРЕБУЕТ ПРОВЕРКИ`
([07-research-log.md](../research/07-research-log.md), п. 3 очереди проверки). Решение
принимается сейчас, потому что оно консервативно: если подпись окажется
возможной иначе, ограничение можно снять, обратное — переписывание архитектуры.

## Решение

Разделяем систему на два контура:

- **Облако (РФ):** оркестратор, разбор ТЗ, matching, движок соответствия,
  обработка КП, экономика, хранилище, аудит.
- **Local agent на ПК клиента (Windows):** браузерные сессии, взаимодействие с
  ЭТП, мост к криптопровайдеру, инициация подписания после подтверждения человеком.

Соединение — исходящее mTLS от локального агента к облаку. Входящих портов на
машине клиента не открываем. Приватный ключ КЭП не покидает контур клиента и не
становится секретом нашего сервиса.

## Последствия

Положительные: ключ ЭП и корпоративные аккаунты остаются у клиента; работаем и
там, где нет публичного API; снимается целый класс юридических и ИБ-рисков;
проще проходить проверку службы безопасности крупного клиента.

Отрицательные: нужен установщик и обновление Windows-агента; отладка сложнее;
работа возможна только при включённом компьютере клиента; часть логики
дублируется на двух контурах.

Смягчение: local agent появляется только в v1. MVP работает без него — на
email-RFQ и открытых источниках ([05-roadmap.md](../product/05-roadmap.md)).

## Альтернативы

- **Чистый cloud SaaS с хранением учётных данных клиента.** Отклонено:
  неприемлемый ИБ- и юридический риск, блокирует продажи в enterprise.
- **Чистое desktop-приложение.** Отклонено: ядро ценности требует централизованных
  данных, накопленной истории и быстрых обновлений моделей.
- **On-premise установка всей системы.** Не отклонено, а отложено как
  enterprise-опция; для первых клиентов слишком дорого в поддержке.
