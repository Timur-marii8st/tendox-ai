# ADR0114: одноразовые приглашения в закрытую бету

Дата: 2026-10-23. Владелец: root. Статус: принят; установлен24Oct2026 по плану3627e90e.

## Контекст

[PRD](../product/11-product-requirements.md) требует мультитенантного профиля.
[Профиль](../architecture/07-company-profile-contract.md) и КП используют личный bearer,
но ручной ввод ключа мешает бета-тестерам. Корпус ЕИС сейчас загружен в отдельный
tenant: новый tenant не должен лишаться публичного поиска или получать чужие КП.

## Решение

- Только администратор через owner connection выдаёт приглашение: компания,
  участник, общий публичный corpus и срок1–168часов (обычно48). По умолчанию новая
  компания; существующая указывается явно для сотрудников одной компании.
  Runtime не может выпускать приглашения или менять привязку corpus.
- Ссылка `/beta-invite#bi_...` содержит256бит случайности во fragment. Fragment
  не отправляется HTTP-серверу; страница удаляет его из URL. GET и загрузка
  страницы не потребляют приглашение; пользователь нажимает кнопку входа.
  Robots noindex/no-follow, Referrer-Policy no-referrer. Ссылку передают лично.
- POST принимает только token; caller company/actor/role запрещены. SQL function
  под FOR UPDATE атомарно потребляет приглашение и создаёт OPERATOR-сессию7дней.
  Повтор, expiry и revoke дают один ответ без раскрытия компании. Успех после
  потери ответа не повторяется автоматически: организатор выдаёт новую ссылку.
- В PostgreSQL только SHA256 секретов. В браузере только HttpOnly/Secure/Strict
  cookie; нет localStorage. Server expiry/revoke проверяется на каждом запросе.
  Выход отзывает сессию; отзыв приглашения отзывает и созданную им сессию.
- Company/actor берутся из сессии. Профили, выбор версии, КП, расходы и audit
  записываются только в private tenant. Все новые таблицы FORCE RLS.
- Общий source corpus привязывается администратором, а не телом запроса.
  Приглашённым доступны только публичные EIS index/global-price/coverage/navigation
  reads. Технические analyses, supplier/browser actions и reviewer/pilot credentials
  не передаются приглашённому. UI скрывает расширенные инструменты этого пилота.
  Quote/shortlist читают ceiling/deadline/holds из corpus, но вычисляют и хранят
  финансовые декларации и профиль в личной компании. КП в corpus не копируются.
- Приглашение не создаёт OWNER, не снимает hard gates и не даёт PARTICIPATE.
  Общая Basic-защита закрытого сайта сохраняется: это не открытая регистрация.
  Самостоятельное восстановление доступа/email identity verification не добавлены.
- Issue/redeem/revoke/logout имеют tenant-scoped audit без plaintext секретов.
  Новые функции SECURITY DEFINER с фиксированным search_path, без dynamic SQL;
  PUBLIC execute отозван, runtime получает только необходимые EXECUTE/SELECT.

## Последствия

Получатель открывает ссылку и нажимает «Войти и заполнить профиль». Рабочий профиль
и КП изолированы от других компаний; сотрудники одной компании разделяют данные.
Смена устройства после использования приглашения требует новой ссылки. Нельзя
пересылать приглашение в общий чат. Стандартный ключевой вход пока сохранён для
существующих операторов. Полнота ЕИС/ТЗ и реальная экономика не становятся PASS.

## Альтернативы

Общий ключ или company_id из URL смешали бы доступы. Автоматическое потребление
GET ломается на preview/scanner. Полная email-регистрация требует отдельного
контракта доставки и восстановления; в этот ограниченный beta slice не входит.
