# ADR-0117 — обход активных закупок44 без товарного запроса

Дата:2026-10-24. Owner root. INSTALLED_BOUNDED; первый live проход8SYNCED/HTTP PASS.
Контракт:[PRD3.1](../product/11-product-requirements.md),
[ADR0116](0116-eis-hybrid-discovery-recovery.md), [evidence129](../eis/search/129-eis-active-sweep.md).

## Контекст

Пилот по«бумага» ограничен одним запросом и3страницами; discovery cooldown
останавливает и обработку уже найденной очереди. Реальная выдача без запроса
содержит более54000активных карточек44. PRICE-первая страница50/50уже в индексе;
PUBLISH_DATE-первая страница39/50в индексе,11пропусков. Это два наблюдения,
не national recall и не гарантия преимущества сортировки для каждого периода.

## Решение

Отдельный coordinator `server-eis-active-sweep.py` использует текущие S201 intake
и V37 queue/evidence. Wrapper `--all-active --as-of YYYY-MM-DD` выбирает только
этот фиксированный entry point. Вход:пустой searchString,44/AF, deadlineFrom текущая
дата Москвы, сортировка публикации↓, публикация дофиксированного as_of включительно.
Echo фильтров и дата публикации каждой карточки проверяются. As_of — фиксированная
верхняя дата прохода, а не обещание обновления будущих публикаций; допустим7дней.

Корень имеет неограниченную нижнюю дату. Переполненный диапазон делится на
последние30дней и весь более ранний хвост; ограниченный диапазон — пополам.
Дети не пересекаются и полностью покрывают родителя. Count>1000 либо заполненная
20ястраница инициируют split. Насыщенный одиночный день читается до20страниц,
затем SATURATED_UNKNOWN, без
ложного complete; дальнейшее разбиение такого дня — отдельный срез.
Неизвестный/изменившийся count и динамическая пагинация не подтверждают полноту.
OBSERVED_PAGES означает только конец наблюдённых страниц, coverage всегда UNKNOWN.

Очереди, попытки и дерево диапазонов — один атомарный tenant-scoped checkpoint.
HTML/immutable Page сначала сохраняются, затем кандидаты и split одной записью.
Номер имеет одного владельца среди очередей всех диапазонов. Split сохраняет
необработанные номера/долги audit родителя. Новое наблюдение переносит владельца,
обновляет candidate/provenance/last_seen, сохраняя attempts/backoff. При долге audit
последнее наблюдение сохраняется отдельно (не более одного на queued number) и
атомарно применяется после закрытия долга; исходный audit source не подменяется.
IN_FLIGHT/backoff сохраняются до сети.
Сначала drain старой очереди, затем discovery, затем оставшийся drain-бюджет.
Ошибки discovery не скрывают результаты уже выполненного intake. Cooldown ждёт
не более61s и повторно захватывает существующий host lease; обход ограничений
источника/CAPTCHA не реализован. Query mode сохраняет прежнюю семантику и hashes.

Наличие50номеров проверяется одним SELECT вместо отдельных чтений каждого номера;
сохранены tenant scope и критерий versions+lexical. Полный exact intake по-прежнему
повторно проверяет версии/проекцию, сохраняет provenance и audit.
За весь проход максимум8попыток с единым прежним S201Budget:180s,18POST,
20downloads,64MiB; protected44/223 budget, SQL5s и shared leases сохраняются.
180s ограничивают recovery; ожидание HTML до61s и запрос до25s могут добавиться
сверх него. Общая source reservation360s сохраняется.

## Границы и последствия

Глобально:256диапазонов,2000элементов очереди,256MiB/5000evidence entries.
Root cycle.json связывает единственный as_of; другой цикл без явного перехода
отклоняется. Эти пределы не умножаются на число partitions или дат запуска. Достижение предела явно останавливает
дальнейший обход; удаления/бессрочного retention нет. Уже INDEXED остаются в state.
Это следующий ограниченный пилот, не бессрочная загрузка всей ЕИС.
223-ФЗ, закрытые/исторические закупки, обновления существующих номеров,
полнота ТЗ и насыщенные одиночные дни не объявляются решёнными.
Source throughput измеряется отдельно от SQL round-trips/лимита попыток.
Полный release gate/review и exact payload нужны до новой production активации.
