# ADR0110 — ограниченный второй сегмент NO_DATA evidence

Дата решения: 2026-10-19. Статус: CANDIDATE, активация не выполнена.
Effective date эксплуатационной policy — время будущей exact-payload активации,
до него действует ADR0079. Владелец root; основание — подтверждённое исчерпание
128MiB и потеря новых raw replies, [диагностика](../operations/121-eis-production-readiness.md).

## Контекст

Удаление старых ответов разрушит разрешение immutable audit references.
Увеличение одного max_page_count не задаёт lifecycle. Нужен ограниченный переход
без изменения существующих записей, токенов, source budgets и статусов ЕИС.

## Решение

Один private root содержит ровно два известных приложению сегмента:
`no-data.sqlite3` и `no-data-overflow.sqlite3`. Лимиты каждого сохраняются:
128MiB DB,96MiB payload,65536rows; всего максимум256MiB DB/192MiB payload/
131072rows. Rollback journals и1-byte lock требуют дополнительного места.
Новые имена/третий сегмент не создаются автоматически.

QUOTA_REACHED/SQLITE_FULL либо достижение лимита allocated pages первого
сегмента разрешают открыть второй. При page_count×4096>=128MiB новая запись
не использует оставшиеся свободные ячейки страниц; replay проверяется до квоты.
IO/busy/unsafe/schema failures не маскируются переходом. Появление второго
сегмента делает переход постоянным: первый используется приложением только
для чтения и replay. Оба файла остаются на месте; export/delete/TTL нет.
Общая OS-блокировка с ожиданием<=1s сериализует решение о переходе и записи;
соединения SQLite сохраняют собственный timeout1s. Раздельный immutable audit
нового наблюдения остаётся tenant-scoped.

Receipt допускает два точных relative_store_path; прежние receipts валидны.
Verifier ищет identity tenant/window/SHA сначала в первом, затем во втором
сегменте; неверные bytes/schema/permissions и недоступность первого не скрываются
поиском во втором. Проверяются прежние raw/manifest hashes и источник.
Hard links и symlinks к DB запрещены. Данные другого tenant не возвращаются.

Отчёт показывает отдельные counters и оставшуюся квоту обоих сегментов,
общий лимит DB256MiB и headroom текущего writable сегмента. Порог80% сохраняется;
ошибки/unknown visibility имеют приоритет над OBSERVE. PASS metadata/audit
не является PASS сохранения raw, отсутствия закупок или полноты ЕИС.

## Последствия и альтернативы

Это ограниченное восстановление записи, не бесконечная retention policy.
После заполнения второго файла остаётся typed FAILED/QUOTA_REACHED. Потерянные
raw ответы за предыдущий период не реконструируются и не получают RETAINED.
До дальнейшего расширения нужен новый проверенный storage/lifecycle контракт.
Rollback к старому reader после появления новых receipts скроет второй файл;
восстановление прежнего кода допустимо только с сохранением совместимого reader.

Удаление старой SQLite, переименование без resolver и автоматическое создание
неограниченного числа файлов отклонены. Изменение лимита одного файла само по
себе не обеспечивает сохранение audit references и конечный resource budget.

Проверки и точная операция активации — [операционный срез](../operations/122-eis-no-data-overflow.md).
