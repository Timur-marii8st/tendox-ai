# ADR-0010: локальный русский OCR на PaddleOCR 3.7 / PP-OCRv5

## Контекст

S4 должен извлекать текст из raster-only PDF без передачи клиентских документов
в сторонний сервис. Каждый распознанный блок обязан иметь координаты и confidence,
потому что результат ниже порога не может стать фактом или hard gate.

На 2026-09-13 PaddleOCR-VL-1.6 является наиболее новой моделью сложного
document parsing и показывает 96,33% на OmniDocBench v1.6. PP-OCRv6 новее
линейки PP-OCRv5, но его единая multilingual-модель не включает русский язык.
VL-выход генеративный и не даёт совместимый с нашим контрактом confidence каждой
строки. PP-OCRv5 multilingual поддерживает русский, возвращает `rec_scores` и
`rec_boxes`; официальный `eslav`-чекпойнт показывает 81,6% и улучшение 31,4%
относительно предыдущего поколения на наборе разработчика.

## Решение

- Использовать локальный PaddleOCR 3.7.0 с `PP-OCRv5_server_det` и
  `eslav_PP-OCRv5_mobile_rec`, языком `ru`, классификацией ориентации,
  выпрямлением документа и ориентацией строк.
- Держать PaddleOCR/PaddlePaddle в optional extra `ocr`; production runtime
  выбирает этот runner на сервере. Клиент не передаёт и не подменяет engine.
- Перед inference сверять SHA-256 байтов с immutable document snapshot,
  принимать только проверенный PDF и не более 200 страниц.
- Запускать inference локально и последовательно через один lazy pipeline.
  Временный PDF удаляется после полного чтения результата.
- Преобразовывать каждую строку в `OcrCandidate` с номером страницы, bbox и
  `rec_score`. Только общий детерминированный порог `0.75` повышает кандидата в
  `ExtractedBlock`; пустой итог остаётся `UNKNOWN/OCR_REQUIRED`.
- Для изолированной среды заранее размещать пять официальных моделей в
  `PADDLE_OCR_MODEL_ROOT`. Если каталог задан, отсутствие любой модели является
  ошибкой конфигурации; документы никогда не отправляются во внешний OCR API.

## Последствия

Обычная установка остаётся лёгкой; OCR-развёртывание требует
`uv sync --extra dev --extra ocr` для разработки или `uv sync --extra ocr` для
runtime. Без локального model root PaddleOCR скачает официальные веса при первом
запуске, поэтому закрытый production-контур должен предзагрузить их при сборке.

CPU inference занимает десятки секунд при холодном старте. В текущем срезе lock
защищает не подтверждённый как thread-safe pipeline; очередь фоновых задач и
несколько worker-процессов будут отдельным операционным решением. Метрики
производителя не заменяют проверку на реальных русских закупочных документах:
пока зафиксирован синтетический raster-only regression на обычной, повёрнутой и
низкоконтрастной размытой страницах.

## Альтернативы

- **PaddleOCR-VL-1.6** — лучше для таблиц, формул и общей структуры, но его
  генеративный результат нельзя напрямую пропустить через текущий confidence gate.
- **PP-OCRv6** — быстрее и новее для поддержанных языков, но текущая официальная
  матрица не включает русский/кириллицу.
- **Облачный OCR** — исключён из этого среза из-за передачи исходного документа
  наружу и отдельной модели доверия.
- **Tesseract и менее новые ONNX-обёртки** — проще, но не дают оснований выбрать
  их вместо актуальной официальной multilingual-модели с измеримым score/bbox.
