# ADR-0102: неизменяемый черновик запроса КП изготовителю

Дата: 2026-10-06. Статус: принято; локальная реализация проверена.

## Решение

Оператор может сохранить внутренний черновик только для одной реестровой
записи с действующим независимым identity/role review и непротиворечивой
полной сводкой. Сервер проверяет exact run/record/proposal/decision IDs,
source/dossier/proposal/decision SHA и сроки. Проверки других записей поиска
не заменяют доказательства выбранного товара.

Количество поступает строкой положительного конечного Decimal. Каноническая
обычная десятичная запись ограничена ста символами: экспонента не должна
вызывать неограниченное расширение, а Decimal context не округляет значение.
Единица, основание количества, до двадцати требований, доставка и срок ответа
вводятся оператором и получают точную manual provenance с actor/time.
Эти требования не объявляются полным проверенным ТЗ.

Одна append-only tenant-scoped таблица с forced RLS сохраняет exact snapshot,
канонический payload, SHA, детерминированный UTF-8 TXT и audit event. Command
replay actor-bound; изменённый payload даёт конфликт. Чтение и скачивание
перепроверяют сохранённые bytes, происхождение ручных полей и source linkage.

Исторический текст не переписывается. Текущая применимость оценивается отдельно:
expiry и явный отрицательный результат дают FAIL; отсутствующее, неполное или
противоречащее evidence остаётся UNKNOWN. Оба состояния блокируют новый draft.

## Границы

Документ всегда `DRAFT_NO_DISPATCH`. Он просит предоставить цену/единицу цены,
НДС, MOQ/шаг партии, наличие/производство, упаковку, оплату, доставку, гарантию
и срок полного КП. Система не подставляет неизвестный контакт или цену.
Website, contact, technical fit, quote и participation остаются UNKNOWN.

API предоставляет только create/read/download. Отправка, согласование внешнего
payload и экономика полученного КП — отдельные существующие/будущие процессы;
этот черновик не предоставляет полномочий для них.
