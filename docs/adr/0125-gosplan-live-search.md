# ADR-0125 — пользовательский поиск через ГосПлан

Дата: 2026-10-29. Статус: IMPLEMENTING, production PENDING. Владелец root.
Дополняет [ADR-0044](0044-eis-source-contract.md) и
[ADR-0116](0116-eis-hybrid-discovery-recovery.md).

## Контекст

Пользователь поручил показывать закупки непосредственно из API ГосПлана, а
официальный индекс ЕИС продолжать пополнять в фоне. Compact list и детальный
ответ имеют разные составы; источники и ограничения описаны в
[исследовании](../research/33-gosplan-internals-review.md).

## Решение

Сервер выполняет ограниченный search обоих законов с серверным ключом и
аутентифицированным tenant, отдельную адресную загрузку выбранной карточки,
общую межпроцессную quota и tenant лимит. Client получает строго типизированные
данные, SHA и aware время наблюдения; upstream 429 и прочие ошибки не становятся
пустой выдачей. Историческая база не является условием видимости. Пагинация
провайдера по offset не гарантирует snapshot или полноту. ЕИС файлы и карточки,
площадки показываются только по допустимым HTTPS адресам; ссылка ЕИС 223,
выведенная по номеру при подтверждённом публичном признаке, маркируется отдельно.

Производные сведения провайдера не подтверждают участие, статус подачи,
timezone срока, полноту ТЗ, версию ЕИС или цены в КП. Статус и срок остаются
UNKNOWN, финансовые допуски не строятся на этой карточке. Даты источника и
возможность усечения списка файлов отмечаются в UI. Документы разных версий
не выдаются за состав актуальной версии. Резервный поиск по базе остаётся доступен.

## Последствия и альтернативы

На live-поиск влияют доступность и квота поставщика; публичная оферта не
гарантирует SLA и требует сверки с первоисточником. Конкретные договор и тариф
пользователя проверять отдельно; предположение о разрешении перепродажи данных
не считается установленным фактом. Перед выпуском — unit/tenant/quota и
retained/live source, UI, полный gate, ограниченный установленный просмотр обоих
законов, контроль секрета и rollback. Просто заменять официальный источник
vendor JSON в canonical базе или выдавать `stage` за допуск нельзя.

## Восстановление discovery

Причина старого отказа без исходной страницы UNKNOWN. После отдельно
аудированного восстановления исходные курсоры продолжены без пропуска старого
интервала. Новая ошибочная страница сохраняется целиком, hold привязывается к
конкретному evidence. Строгий parse_page по-прежнему отвергает null. Для отдельно
проверенной страницы предложена процедура: сохранить исходные байты и SHA,
валидные подсказки и незакрытые строки UNKNOWN с audit; другие нарушения остаются
блокирующими. Курсор и durable marker продолжают исходный интервал, данные не
становятся официальными, полнота остаётся UNKNOWN. Повтор exact плана должен быть
идемпотентным; выпуск и выполнение требуют review, полного gate и cycle lease.
