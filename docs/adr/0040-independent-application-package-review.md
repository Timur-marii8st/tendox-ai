# ADR-0040: независимая проверка exact комплекта заявки

Дата: 2026-09-21  
Статус: Accepted for the local pilot

## Контекст

S93 фиксирует цену, перечень требований и файлы будущей заявки, но сам перечень
составлен оператором. Покрытие этого перечня не доказывает, что все формы и
подтверждения из закупочной документации найдены и корректно заполнены.
Требуется независимое решение по точному immutable пакету без выдачи права на
подпись или отправку.

## Решение

Ввести отдельную роль `APPLICATION_REVIEWER`. Проверяющий не может быть автором
пакета. Он открывает один package ID и SHA-256, получает exact case/participation
evidence и оригиналы только связанных с пакетом документов. Каждый требуемый
элемент получает `PASS | FAIL | UNKNOWN`, основание и ссылки на проверенные
вложения; каждый файл получает отдельный verdict. `PASS` строки требует проверки
всех сопоставленных ей файлов. Проверяющий отдельно оценивает полноту перечня
по документации и цену, фиксирует IDs проверенных документов заказчика и
основания. Документы не меняют policy или permissions.

Сервер вычисляет terminal verdict: любой известный `FAIL`, подтверждённый
пропуск, отклонённая цена или истёкший deadline дают `FAIL`. `PASS` требует всех
построчных и файловых `PASS`, явно подтверждённого полного перечня с каждым
указанным источником, подтверждённой цены, действующего deadline и текущего
`PARTICIPATE` при цене не ниже актуального floor и не выше НМЦК. Остальные
случаи остаются `UNKNOWN`. Текущая рекомендация, два серверных gate, actor/time,
точный package digest и `external_action_authorized=false` входят в digest
решения.

Один пакет получает не более одного append-only review. Decision, audit
`application.package_reviewed` и idempotency receipt записываются атомарно в
tenant-scoped таблицы под RLS/FORCE RLS. GET реконструирует решение из exact
пакета и времени review. Отдельный BFF использует server-only reviewer token,
перед POST перечитывает пакет и не принимает caller-supplied итоговый status.

## Последствия

Проверка имеет явное человеческое основание и различает известный пропуск от
неразрешённой полноты. Положительное решение подтверждает review конкретного
пакета, но не является разрешением внешней подачи. До подписи и отправки нужен
отдельный exact-payload approval с ограниченным сроком действия; этот workflow
остаётся следующим срезом.
