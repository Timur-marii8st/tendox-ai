# ADR-0020: полнота блокирует положительный document compliance

Дата: 2026-09-16  
Статус: принято

## Контекст

ADR-0018 отделил найденные требования от доказательства полноты документа. Без
явного потребителя движок мог корректно выдать `COMPLIANT` по известным
требованиям, хотя `CompletenessAssessment` оставался `UNKNOWN`.

## Решение

`evaluate_document_mapping` является типизированной границей между
`FactMappingResult` и compliance engine. Она принимает `LineItem` только с точным
набором requirements из mapping и проверяет согласованность извлечённых срока и
режима эквивалента, когда они присутствуют.

Итог определяется fail-closed:

- известный mandatory `FAIL` остаётся `FAIL` независимо от полноты;
- при `completeness=UNKNOWN|FAIL` любой иной результат становится
  `NEEDS_CLARIFICATION`;
- `COMPLIANT` возможен только при `completeness=PASS` и положительном результате
  детерминированного compliance engine.

## Последствия

- пустое или частичное автоматическое извлечение не даёт технический допуск;
- доказанное несоответствие не скрывается за неопределённостью полноты;
- ручной S1 остаётся отдельным workflow и не получает автоматическую полноту;
- persistence completeness review и его подключение к case ingestion остаются
  отдельным срезом.

## Альтернативы

- Заменять любой результат при неполноте на `UNKNOWN` — отклонено: это скрывает
  уже доказанный mandatory `FAIL`.
- Встроить document types в чистый domain compliance — отклонено: домен не должен
  зависеть от document pipeline.
- Считать `blocks_mapped == blocks_total` полнотой — отклонено ADR-0018.
