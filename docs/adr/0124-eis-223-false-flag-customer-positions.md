# ADR-0124 — позиции заказчика при `jointLot=false`

Дата: 2026-10-29. Статус: локальный кандидат; выпуск и приёмка PENDING.
Владелец root. Дополнение к [ADR-0123](0123-eis-223-joint-position-projection.md).

## Контекст

Исходный XML 223-ФЗ содержит `jointLot=false` и вложенные группы заказчиков с
позициями. Схема называет флаг признаком совместной закупки. Текущий обработчик
останавливает всё окно; интерфейс называет группы совместной закупкой. На
сохранённом исходном XML `32616514256` v1 с SHA
`6dcfde0bb5ab1188d5b8aca8b59d9c352860951f1fbc1d93f6e145f894c20347`
подтверждены один заказчик и одна позиция. Последний failed ответ отдельно не
сохранён; его состав известен только по ограниченной диагностике.

## Решение

Для проверенной QName/topology извлекать все customer/item scopes в существующую
source-bound projection, сохраняя `source_item_coverage=UNKNOWN` и причину
`JOINT_FLAG_FALSE_WITH_CUSTOMERS`. Исходный XML и позиции не переосмысляются;
не утверждать, что флаг ошибочен или закупка совместная. UI показывает нейтральную
формулировку и необходимость проверки источника. Полнота ТЗ и экономика UNKNOWN.
При несовместимых прямых и customer позициях, неподдержанном флаге или несопоставленных
позициях обработка остаётся закрытой. Прежние JSON и digest для `true` неизменны.

## Последствия и альтернативы

Источник сохраняется с audit и точной XML-привязкой, но семантика участников при
`false` не считается доказанной. Обновлённый reader/UI должен быть развёрнут до
producer, иначе старый UI может неверно назвать такую закупку совместной.
Пропуск группы теряет позиции; трактовка `false` как `true` создаёт ложный факт.
Оба варианта отвергнуты. До установки необходимы PG/RLS/replay, выпускной gate
точного снимка и проверка на фактическом source-комплекте.
