# ADR0091: операторская связь исходных фрагментов с позицией

Дата: 2026-10-06. Статус: принято и выпущено в S221; evidence в docs103.

## Контекст

S220 находит карточки и публичные цены по наименованию позиции. S219 показывает
сохранённый body-only DOCX, но связь текста с позицией не проверена. Для оценки
комплектации необходимо сохранить конкретные исходные требования; утверждение
всего документа полным ТЗ по его имени недопустимо.

## Решение

Добавить отдельную immutable операторскую связь exact позиции с selected spans
из cached review. Клиент передаёт только bounded selectors. Сервер сохраняет
выбранный текст, исходную provenance и оба digest — исходных bytes и анализа.
Всю связь можно проверить и повторно открыть без сети. OPERATOR_LINKED не
становится approved requirements и не даёт технический PASS.

## Последствия

Уже можно собрать проверяемый контекст позиции для сравнения предложения и
RFQ. Существующий reviewed-requirements контракт и его completeness gates
не ослабляются. Добавление новых поставщиков и нормализация требований
выполняются следующими отдельными срезами.

## Совместимость установки

S221 добавляет source0 API и отдельную таблицу; парсеры, intake-контракты, cron
и лимиты загрузок не меняются. Установка сериализуется через
`vibe-seller-state/backend-deploy.lock`, затем web deployment lock. Миграция
выполняется до переключения API с lock timeout 5s / statement timeout 60s.
Старые работающие worker images совместимы с additive schema и продолжают
импорт. Deployment не захватывает dispatch/import leases и не создаёт priority
marker; он не пересоздаёт работающие загрузчики. При занятой DDL-блокировке
миграция откатывается; повтор установки не требует остановки загрузки ЕИС.
Source0 live proof считает только собственные association/audit rows, поскольку
обычная фоновая загрузка может одновременно менять общий объём индекса.
