# ADR-0039: exact proposal комплектации заявки после APPROVED

Дата: 2026-09-21  
Статус: Accepted for the local pilot

## Контекст

S92 сохраняет внутреннее независимое `APPROVED` участия, но не содержит файлов,
цены и точного payload будущей заявки. Документация закупки может требовать
разные формы и подтверждения; существующая модель case не извлекает полный
обязательный перечень автоматически. Создание комплекта не должно выдавать
ложный вывод о полноте или разрешать юридически значимое действие.

## Решение

Оператор вручную перечисляет необходимые документы с `kind`, названием и
точным provenance в immutable документе роли `TENDER_REQUIREMENTS`. Каждой
заявленной строке соответствует хотя бы один уже загруженный immutable файл
роли `APPLICATION_ATTACHMENT`; файл может покрывать несколько строк. Для каждого
файла фиксируются document ID, SHA-256, имя при подаче, оригинальное имя и тип.
Номера строк, связи, имена файлов и документы проверяются на полноту внутри
заявленного списка, уникальность и точное tenant-scoped соответствие байтам.

Repository перечитывает exact `APPROVED` decision, evaluation и case, сверяет
их digests и перед сохранением заново вычисляет case на текущее timezone-aware
время. Требуются действующий deadline, `PARTICIPATE`, цена в RUB без НДС не ниже
актуального floor и не выше НМЦК. Пакет содержит текущую рекомендацию, цену,
все строки, exact identity/digest и actor/time. Его состояние всегда
`PENDING_REVIEW / UNKNOWN`, `external_action_authorized=false`.

Один decision получает не более одного append-only пакета. Package, audit
`application.package_prepared` и idempotency receipt пишутся атомарно в
tenant-scoped таблицы под RLS/FORCE RLS. GET повторно сверяет payload с
колонками, исходным решением и документами. API разрешает POST только OPERATOR;
AUDITOR читает. Экран использует server-only operator credential и перед POST
перечитывает exact decision digest.

## Последствия

Пакет воспроизводим и не подменяет исходные документы. Покрытие заявленных
оператором строк не доказывает, что оператор нашёл *все* требования закупки:
независимый review полного состава и exact package digest остаётся следующим
срезом. Пакет не подписывает, не отправляет заявку и не выдаёт approval на
внешнее действие; такой approval потребует отдельного exact payload.
