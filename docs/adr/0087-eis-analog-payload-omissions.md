# ADR 0087 — явные пропуски в ограниченной выдаче аналогов

Дата: 2026-10-06. Статус: принят; deployment evidence — docs99.

## Причина

Одна большая карточка в первых20 может блокировать весь запрос. Повышение
лимитов памяти не гарантирует завершение и меняет предсказуемость ресурсов.

## Решение

До hydration проверять SQL octet_length JSONB. Оставить целевой hard limit,
первые20/order/sentinel, tenant/source-hold/SHA gates и общий byte budget.
Кандидаты сверх лимита получают typed omission, привязанную к exact notice
version/XML SHA. Счётчики рассмотренных карточек/позиций не включают пропуски.
Без refill: лимит выборки сохраняет прежний смысл. Другие integrity errors
продолжают блокировать. Policy v2 явно меняет wire contract; web выпускается
первым с dual v1/v2 validation. Неизвестная сопоставимость остаётся UNKNOWN.

## Последствия

Доступная часть выдачи работает при сохранённых ограничениях памяти. Отчёт
прямо показывает пробелы, включая ситуацию все20omitted. Это не полный
технический анализ крупных карточек и не подтверждение полного охвата ЕИС.
Отдельное расширение проекций/позиционных чтений возможно после измерений.
